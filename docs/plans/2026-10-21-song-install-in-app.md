# 게임 안에서 곡 넣기 — bpm을 일반 사용자에게서 숨기기

날짜: 2026-10-21 · 대상: `crates/beetle-app`, `crates/bms-package-manager`, `crates/bpm-gui`

## 문제

일반 BMS 유저가 아는 것은 "곡을 받아서 넣는다"뿐이다. 지금은 곡을 넣으려면 실행 파일을 두 개 알아야 한다.

- `beetle-app`에 파일을 끌어다 놓으면 **설치되지 않고 한 번 열린다**(`main.rs` `open_dropped_file`).
  `.bmsp`/`.bms`만 받고 폴더나 zip은 "지원하지 않는 파일" 토스트로 끝난다.
- 실제 설치(폴더, 압축 파일, `.bmsp`, `.bmdp`, 배경 영상)는 `bpm-gui`의 `tasks::add_path`에만 있다.
- 첫 실행 안내(`strings.rs` 빈 라이브러리 안내)는 "곡 관리자로 설치 / 끌어다 놓기 / songs 폴더" 세 갈래를
  제시한다. 같은 일을 하는 방법이 세 가지라서 오히려 고민하게 만든다.

## 목표

- 게임 창 하나에서 곡 넣기, 지우기, 기존 폴더 연결이 끝난다. 패키지, 레지스트리, 버전 같은 말은 보이지 않는다.
- `bpm-gui`는 난이도표, 온라인 허브, 차분, 패키지 만들기를 다루는 **고급 도구**로 남는다.
  일반 사용자가 반드시 열어야 하는 프로그램이 아니다.
- 설치 로직은 한 곳에만 둔다. 게임과 `bpm-gui`가 같은 함수를 부른다.

## 단계

### S1 — 설치 진입점을 라이브러리로 옮기기
- `bpm-gui/src/tasks.rs`의 `add_path`, `import_folders`, `install_bmsp`와 압축 해제 분기를
  `bms-package-manager::add`(가칭)로 옮긴다.
- 반환값은 문장이 아니라 구조체 `AddReport { installed, linked, skipped: Vec<(이름, 이유)> }`로 바꾼다.
  문장은 각 UI가 자기 문자열 표에서 만든다(게임은 `strings.rs`, 3개 언어).
- 진행 콜백과 취소 플래그는 지금 `install_with_progress`의 형태를 그대로 쓴다.
- `bpm-gui`는 새 함수를 부르도록 바꾸고 동작은 그대로 둔다. 테스트로 분기별 결과를 고정한다.

### S2 — 게임 창에 끌어다 놓으면 설치
- `open_dropped_file`에서 `.zip/.rar/.7z`, `.bmsp`, `.bmdp`를 받으면 **설치**하고, 폴더는 **연결**한다(결정 1·2). 설치는 백그라운드
  워커가 하고(INV-5), 화면에는 토스트 진행 표시를 띄운다. `.bms` 단일 채보는 지금처럼 바로 연다.
- 여러 파일을 한꺼번에 놓으면 큐에 쌓아 하나씩 처리하고, 끝나면 요약 토스트를 하나만 띄운다
  (예: "3곡 추가, 1곡 건너뜀"). 건너뛴 이유는 토스트를 누르면 목록으로 보여 준다.
- 설치가 끝나면 기존 재스캔 경로(`library_mtime`)로 목록을 갱신하고, 새로 들어온 곡에 커서를 둔다.
- 플레이 중에 놓인 파일은 결과 화면까지 보류한다.
- 구현(2026-10-22, `crates/beetle-app/src/install.rs`): 진행 토스트는 사라지지 않고 남아 있고, 누르면 취소된다.
  요약 토스트는 건너뛴 항목이 있으면 8초 동안 남고, 누르면 "넣지 못한 곡" 목록이 열린다(ESC/Enter로 닫음).
  `.bmsp`를 놓으면 이제 바로 플레이하지 않고 설치한다. 개발용 `BEETLE_DEV_DROP`으로 시작할 때 놓기를 흉내 낸다.

### S3 — 첫 실행: 기존 BMS 폴더 연결
- 빈 라이브러리 안내를 버튼 두 개로 줄인다: **"기존 BMS 폴더 연결"**, **"곡 파일 끌어다 놓기"**(설명만).
- 폴더 연결은 복사하지 않고 `library.dat`에 경로만 추가한다(`library::save_library`, 결정 1). 폴더 선택은 `bpm-gui/file_dialog.rs`의 COM 호출을
  공용 위치로 옮겨 함께 쓴다.
- 설정 화면에 "곡 폴더" 항목을 두어 연결 목록을 보고, 추가하고, 끊을 수 있게 한다(`options_table.rs`).
- 구현(2026-10-22, `crates/beetle-app/src/song_folders.rs`): 고른 폴더는 끌어다 놓은 폴더와 같은 큐(`install.rs`)로
  들어가 연결되므로 진행·요약 토스트도 같다. 설정 "곡 폴더" 행(시스템 묶음)에서 ENTER로 목록을 열고, ↑↓로 고르고,
  DEL이나 "연결 끊기" 버튼으로 끊고(파일은 그대로, 끊은 뒤 다시 읽기), "폴더 추가"로 대화상자를 연다.
  대화상자는 `bms-package-manager::file_dialog`로 옮겨 `bpm-gui`와 함께 쓴다. 안내에서 빠진 "곡 관리자 열기"와
  "songs 폴더 열기" 버튼과 그 코드(`shell_open`)는 지웠다 — S4 "폴더 열기"와 S6 "고급 도구"에서 다시 필요하면 기록에서 되살린다.

### S4 — 선곡 화면에서 관리
- 곡의 컨텍스트 메뉴(우클릭 / 키 하나): **폴더 열기**, **삭제**(확인 대화), 버전이 둘 이상일 때만 **버전 선택**.
- 삭제 정책은 컬렉션 설계 §9.2를 따른다. 연결된 폴더의 곡은 지우지 않고 "목록에서 숨기기"만 제공한다.
- 구현(2026-10-22, `crates/beetle-app/src/song_menu.rs`): 곡 줄을 우클릭하거나 M으로 연다. 곡의 출처는 로드 경로로 가른다
  (`<bmsp>::<항목>`이면 패키지, 아니면 폴더 — `songs/`도 폴더로 본다). 패키지 곡의 "삭제"는 그 패키지의 모든 버전을
  지우고(`PackageManager::uninstall`), 함께 들어온 채보가 여럿이면 확인 줄에 그 수를 말한다. "버전 고르기"는 `set_active`.
  둘 다 끝나면 다시 읽고 결과 토스트를 띄운다. 폴더 곡은 숨기기만 하며, 숨긴 채보 ID를 `hidden.dat`(작업 폴더)에 적고
  라이브러리를 읽을 때 뺀다. 설정 "숨긴 곡" 행에서 ENTER로 모두 다시 보인다. 폴더 열기는 `ShellExecuteW`("explore").

### S5 — `.bmsp` 파일 연결
- 탐색기에서 `.bmsp`를 더블클릭하면 게임이 열리고 S2 경로로 설치된다. 이미 실행 중이면 그 창으로 넘긴다
  (단일 인스턴스: 이름 있는 뮤텍스와 `WM_COPYDATA`, 새 크레이트 없음).
- 레지스트리 등록(HKCU)은 설정 화면에서 사용자가 켤 때만 한다.

### S6 — `bpm-gui` 자리 정리
- 선곡 화면의 "곡 관리자 열기"는 "고급 도구"로 이름을 바꾸고 첫 실행 안내에서 뺀다.
- `bpm-gui`는 계속 함께 배포한다(결정 3). "곡 추가"도 유지한다(같은 함수를 쓰므로 유지 비용이 없다).
- 난이도표의 "없는 곡 받기"를 게임 안으로 들일지는 S1~S4를 쓴 뒤 다시 정한다.

## 결정 (2026-10-21 확정)

1. **기존 폴더는 참조가 기본이다.** 이미 압축이 풀린 폴더를 연결하면 복사하거나 다시 묶지 않고
   `library.dat`에 경로만 추가한다. 복사는 고급 도구(`bpm-gui`)에서만 한다.
   폴더를 창에 끌어다 놓아도(S2) 같은 규칙으로 연결만 한다.
2. **zip/rar/7z는 `.bmsp`로 묶어서 설치한다.** 압축을 임시 폴더에 풀고 로드 성능을 기준으로 고른 프로필
   (`PackProfile::Turbo`: 사전 디코딩 아틀라스)로 패킹해 `packages/`에 설치한 다음 임시 폴더를 지운다.
   곡을 불러오는 속도가 빨라지고(INV-3), 결정론적 패킹(INV-6)으로 중복을 판별할 수 있으며,
   컬렉션 설계 §9.3의 로드 위치 규칙과도 맞다. 큰 곡은 패킹이 오래 걸리므로 진행 표시와 취소는 필수다.
3. **`bpm-gui`는 계속 함께 배포한다.** 일반 사용자의 기본 경로에서는 빠지지만, 난이도표, 온라인 허브,
   차분, 패키지 만들기, 폴더 복사를 맡는 고급 도구로 유지한다. 없앨 계획은 없다.

## 하지 않는 것

- 게임 안 온라인 스토어나 검색. 배포처 문제는 따로 다룬다(없는 곡 내려받기 설계 참고).
- 기존 `songs/` 폴더 방식 제거. 지금처럼 계속 동작한다.

## 크기와 불변식

- 새 크레이트 없음. 다만 `beetle-app`은 `bms-package-manager`를 개발 의존성으로만 쓰고 있었으므로 S2에서
  일반 의존성으로 옮겼다(`ureq`는 링크되지 않음).
- S2 측정(릴리스, 2026-10-22): `beetle-app.exe` 3,458,048 → 4,079,104 바이트(+607 KB, +18%).
  `cargo bloat` 기준 주요 증가분은 `flacenc` 약 106 KB(Turbo 사운드 아틀라스의 FLAC 묶음, 결정 2의 비용),
  `bms_package_manager` 약 87 KB, `bms_package` 쓰기 쪽 약 43 KB, `zopfli` 약 30 KB(`zip`의 `deflate` 기능),
  `serde_json` 약 29 KB, 그리고 `std`(스레드, 파일, 외부 7-Zip 프로세스) 증가다.
- 설치와 압축 해제는 전부 워커 스레드에서 한다(INV-5). 오디오와 입력 스레드는 건드리지 않는다.
