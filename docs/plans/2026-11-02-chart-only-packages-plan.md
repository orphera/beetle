# 채보만 든 패키지 (2026-11-02, 계획)

B18에서 정리할 때 "다른 곳에 없는 채보는 남기고 키음만 치우기"를 했다([2026-11-01-package-by-song-plan.md](2026-11-01-package-by-song-plan.md) 4.5). 패키지는 안의 파일만 바꿀 수 없어서 새 패키지로 다시 묶어야 했다. 이 문서는 한 걸음 더 나간다: 채보와 키음을 처음부터 다른 패키지에 둘 수 있게 한다. 다만 저장소 전체를 나누지는 않고, **나눌 이유가 있을 때 넣으면서 나눈다.**

## 1. 왜 전부 나누지 않나

채보 패키지와 애셋 패키지로 저장소 전체를 나누는 안을 먼저 따져 봤다.

얻는 것:

- 판을 치우는 일이 애셋 패키지 하나 지우기가 된다. 다시 묶기(4.5)가 필요 없다.
- 판 = 애셋 패키지 하나. 판 고르기가 구조와 맞는다.
- 차분은 처음부터 채보만 든 패키지가 원본 애셋을 가리키는 모양이다. 스펙의 `base_package`(모델 A, [bms_package_system.md](../specs/bms_package_system.md) 38.1)와 같은 생각이다.

얻지 못하거나 새로 생기는 것:

1. **가장 큰 중복은 그대로다.** B18 측정(4.7)에서 겹치는 키음 1.4GB는 거의 모두 서재 폴더와 패키지 사이에 있었고, 패키지끼리는 0이었다. 서재 폴더는 사용자 파일이라 나누지 않는다.
2. **채보와 키음을 잇는 근거가 약해진다.** 지금은 채보 옆의 키음이 가장 확실한 근거다. 묶기(B17)가 틀려도 자기 폴더 키음으로 친다. 나누면 연결이 전부다. 키음 이름이 `01.wav`처럼 번호뿐이면 묶기 규칙 2(빌려 쓰는 키음)도 걸리지 않는다(`mostly_serial_names`).
3. **"같은 애셋"의 경계가 흐리다.** 실제 팩은 90%만 같거나 몇 파일만 다르다. 이를 깔끔히 다루려면 파일 단위 공유, 곧 내용 주소 저장(4.6)이 되는데, 측정 결과 이 서재에서는 얻는 것이 없어 뺐다.
4. `.bmsp` 하나 = 곡 하나로 주고받는 모델과 어긋난다. 저장소 배치, `registry.json`, 로더, `bpm-gui`, 내보내기가 모두 바뀐다.

그래서 저장소는 지금대로 두고, 채보만 든 패키지를 **한 종류 더** 받아들인다.

## 2. 원칙

- **패키지 형식과 저장소는 그대로다.** 채보만 든 패키지도 보통 `.bmsp`다. 다른 점은 매니페스트에 "어느 곡의 키음으로 치는지"를 적는 것뿐이다.
- **연결은 적어 둔다. 추측하지 않는다.** 채보만 든 패키지는 묶기 휴리스틱에 기대지 않고 매니페스트의 기록으로 곡에 붙는다.
- **기록은 어디서나 같은 뜻이어야 한다.** 곡 고정 id(`songs.dat`)는 이 컴퓨터에서만 뜻이 있다. 그래서 바이트로 정해지는 채보 id(`ChartId`)를 적는다.
- **판정은 B17·B18의 함수를 쓴다.** 새 규칙을 만들지 않는다(`same_song::judge`, `key_sets`, `grouping::group`).
- **사용자 파일은 지우지 않는다.** 바꾸는 것은 bpm이 설치한 패키지뿐이다.
- 개발 단계이고 사용자는 한 명이다. 옛 형식의 이전 안내는 만들지 않는다.

## 3. 설계

### 3.1 매니페스트: `base`

채보만 든 패키지의 매니페스트에 확장 필드(`Manifest::extra`, 형식 버전은 그대로)를 둔다.

```json
"base": {
  "charts": ["<ChartId>", "..."],
  "package": "original.artist.song"
}
```

- `charts`: 키음을 빌려 오는 곡의 채보 id들. 넣을 때 그 곡에 있던 채보 중 몇 개(기본: 빌려 오는 판이 있는 위치의 채보 전부)를 적는다. 이 중 하나라도 가진 곡에 붙는다.
- `package`: 빌려 오는 판이 패키지일 때 그 id(스펙의 `base_package.id`). 안내용이다. 판이 서재 폴더면 없다.
- 스펙 38.1의 `base_package`는 정보 제공용 필드로 남겨 두고, 이 계획이 쓰는 필드는 `base`로 한다. 구현하면서 스펙 38.1을 이 필드에 맞게 고친다.

### 3.2 묶기: 규칙 0에 넣기

- 스캔은 패키지 위치를 읽을 때 매니페스트의 `base.charts`를 `collection::Location`(게임은 `SongPlace`)에 함께 담는다.
- `grouping::group`의 규칙 0(사용자 link)에 "이 위치의 채보 + `base.charts`"를 한 묶음으로 더한다. 사용자의 분리(`splits`)는 여전히 이긴다.
- 그러면 로더는 바꿀 것이 없다. 지금도 빠진 키음을 곡의 다른 위치에서 찾는다(`loader::SoundPlaces`).

### 3.3 넣을 때 나누기

`add_path_judged`가 판정한 뒤 다음 경우에 받은 것을 그대로 설치하지 않고 채보만 든 패키지로 만든다. 판정은 위치(곡 폴더, 패키지 안 디렉터리)마다 한다.

| 판정 | 지금 | 바꾼 뒤 |
|---|---|---|
| 새 채보, 키음이 기존 판과 같은 세트 | 전부 설치(키음 중복) | **새 채보와 키음 아닌 파일만 설치**, `base`는 그 판 |
| 새 채보, 자기 키음이 거의 없음(차분 압축 파일) | 그대로 설치, 묶기 규칙 2에 기댐 | 그대로 설치하되 **`base`를 적음** |
| 이미 있음 | 묻고 건너뜀 | 그대로 |
| 다른 키음 세트 | 묻기: 추가 / 교체 / 건너뛰기 | 그대로(새 판이다) |
| 새 곡, 후보 | 설치 | 그대로 |

- "키음 아닌 파일"은 그림, 영상, 텍스트처럼 기존 판에 없는 것이다. 기존 판에 같은 이름·같은 크기의 파일이 있으면 뺀다(`key_sets::Files::same`과 같은 기준).
- 새로 묶는 패키지의 id는 원본 id에 접미사를 붙인다(예: `<id>.charts`). 원본 매니페스트의 이름·작가는 그대로 둔다. 다시 묶기는 4.5의 `PackageBuilder` 경로를 쓰므로 INV-6은 지켜진다.
- 묻지 않는다. 바뀌는 것은 저장 방식뿐이고 플레이에는 차이가 없기 때문이다. 넣기 보고(`AddReport`)에 "곡 X에 채보 N개 (키음은 기존 판 사용)"로 알린다.
- 압축 파일은 이미 풀어서 판정하므로, 채보만 담은 빌더를 바로 만들 수 있다. B16(한 곡씩 풀고 넣고 지우기)을 할 때 같은 자리에 들어간다.

### 3.4 정리(4.5)를 이 형식으로

- 4.5의 다시 묶기 결과는 채보만 든 패키지다. 다시 묶을 때 `base`(첫 좋은 판)를 적는다. 그러면 묶기가 휴리스틱에서 기록으로 바뀐다.
- id는 그대로 두고(같은 패키지의 새 상태), 매니페스트에만 `base`를 더한다.

### 3.5 기존 중복 줄이기 (측정 뒤에)

B18 측정에서 "새 채보" 21곳은 같은 팩의 폴더본과 패키지본인데 한쪽에 채보가 더 있는 경우다. 패키지 쪽에 채보가 더 있으면, 지금 정리는 그 패키지를 지우지 못한다. 같은 세트이니 "음질이 나쁜 판"도 아니다.

- 이런 패키지를 채보만 든 패키지로 바꾸는 정리를 더한다: 패키지 위치의 세트가 서재 폴더 세트와 같고, 폴더에 없는 채보가 있을 때. 키음은 폴더 판에서 빌린다(`base.charts`는 폴더의 채보).
- 먼저 잰다: 이 조건에 맞는 위치 수와 되찾는 바이트. 측정 도구(`crates/bms-package-manager/examples/package_measure.rs`)를 넓힌다. 작으면 하지 않는다.
- 이 경우 키음이 사용자 폴더에만 남는다. 사용자가 그 폴더를 옮기거나 지우면 채보가 키음을 잃는다. 그래서 3.6의 안내가 먼저 있어야 한다.

### 3.6 빌려 오는 판이 없어질 때

- 스캔은 채보만 든 패키지의 곡에 온전한 판이 하나도 없으면 그 채보를 "키음 없음"으로 표시한다(지금 사본의 키음 누락 판정과 같은 자리, B2).
- 곡 메뉴의 패키지 삭제와 정리(`key_sets::going`)는 채보만 든 패키지가 기대는 마지막 판을 치우지 않는다. 지금도 빌려 쓰는 위치는 `partial`로 지켜지므로, `base`로 붙은 위치가 `partial`에 들어가는지만 확인하면 된다.
- 사용자가 지우려 하면 "채보만 든 패키지 N개가 이 키음을 써요"라고 묻는다.

### 3.7 내보내기

- 채보만 든 패키지를 내보낼 때 고른다: 그대로(받는 쪽에 원본이 있어야 함) / 원본 키음과 합쳐 하나로. 기본은 합치기다. `.bmsp` 하나 = 곡 하나로 주고받는 모델을 지키기 위해서다.
- 합칠 때도 빌더와 정렬이 같으므로 결정론적이다(INV-6).

## 4. 순서

1. **측정**(3.5): 같은 세트인데 패키지에만 채보가 더 있는 위치 수와 바이트, 앞으로 넣을 때 3.3이 아낄 크기의 예(같은 팩 다시 넣기).
2. **매니페스트와 묶기**(3.1, 3.2): `base` 읽기·쓰기, 스캔이 `base.charts`를 담기, 규칙 0. 테스트: 번호뿐인 키음 이름의 채보만 든 패키지도 곡에 붙는다.
3. **정리에 `base` 적기**(3.4): `repack_without`이 `base`를 받는다. End Time, x-Aria에 실제로 적용하고 게임에서 친다.
4. **넣을 때 나누기**(3.3): `add_path_judged`, `bpm add`의 보고, 게임·`bpm-gui`의 알림 문구.
5. **안내와 보호**(3.6).
6. **기존 중복 줄이기**(3.5): 1의 측정이 충분할 때만.
7. **내보내기**(3.7).

## 5. 열린 질문

- `base.charts`에 몇 개를 적을까. 전부 적으면 확실하지만 길어진다. 판의 채보가 수십 개인 팩 폴더도 있다. 우선 그 위치의 채보 전부를 적고, 길이 문제가 보이면 줄인다.
- 채보만 든 패키지에 키음이 조금 있는 경우(차분이 키음 몇 개를 더함)는 그대로 둔다. 로더는 자기 위치를 먼저 보므로 문제없다.
- 같은 채보만 든 패키지가 서로 다른 두 곡의 `base`를 가리키게 되면(묶기 분리 뒤 등) 사용자의 분리를 따르고, 남는 쪽에 붙인다.
