# 패키지 관리를 곡 단위로 (2026-11-01, 계획 초안)

B17에서 "같은 채보 / 같은 곡 / 같은 키음 세트 / 더 나은 음질"을 가리는 기준이 생겼다([2026-11-01-song-grouping-plan.md](2026-11-01-song-grouping-plan.md)). 지금 패키지 관리는 이 기준 없이 "어디서 왔나"(패키지 id, 설치 상태 해시)로만 구분한다. 이 문서는 패키지 관리도 같은 기준을 쓰게 바꾸는 계획의 초안이다. 아직 구현 전이고, 순서와 범위는 측정을 보고 다시 정한다.

## 1. 지금 상태 (코드에서 확인)

### 1.1 판정 기준 (B17에서 생긴 것)

| 단위 | 같다고 보는 기준 | 코드 |
|---|---|---|
| 채보 | 바이트가 같다 | `beetle_core::ChartId` |
| 위치 | 폴더, 또는 패키지 안 디렉터리 하나. 한 위치는 언제나 한 곡 | `grouping::Copy::place`, `songs::place_key` |
| 곡 | 위치를 묶는다: 사용자 link → 같은 채보 → 차분이 빌려 쓰는 키음 → 제목·아티스트+키음 겹침 | `crates/bms-package-manager/src/grouping.rs` |
| 키음 세트 | 차트가 선언한 이름의 90%를 가진 위치. 겹치는 파일 크기가 모두 같으면 같은 세트 | `crates/bms-package-manager/src/key_sets.rs` |
| 음질 | 머리 정보(형식, 샘플레이트, 비트 깊이, 채널, 비트레이트)로 "확실히 낫다" | `crates/beetle-core/src/audio_info.rs` |

### 1.2 패키지 관리

- 설치 단위는 패키지다. `registry.json`의 `PackageRecord`가 패키지 id마다 설치 상태(`state_hashes`, 상태 해시 → 경로)와 쓰는 상태(`active_state`)를 가진다. 곡 메뉴의 "버전 고르기"는 이 상태를 바꾼다.
- 넣기(`crates/bms-package-manager/src/add.rs`의 `add_path`)는 받은 것의 종류만 본다. 폴더는 `library.dat`에 연결하고, 압축 파일과 `.bmsp`는 패키지로 설치한다. `.bga.bmsp`는 배경 영상, `.bmdp`는 업데이트다. 이미 있는 곡과 같은지는 보지 않는다.
- 같은 곡인지는 다음 스캔에서야 드러난다(`songs.cache`의 `groups`·`places`).

## 2. 문제

1. **같은 내용이 두 번 있다.** B17 측정에서 위치가 둘 이상인 곡은 96곡이었다. 그중 세트 쌍 100개를 비교했더니 94쌍이 같은 세트였다. 대부분 같은 팩의 폴더 등록본과 패키지 설치본이다. 디스크를 두 번 쓰고, 목록과 정리 판단에서도 위치 두 곳으로 다룬다.
2. **"버전"이 두 가지다.** 패키지의 설치 상태와 곡의 키음 세트 선택이 따로 있다. 곡 메뉴에도 "버전 고르기"와 "키음 세트 고르기"가 따로 있지만, 사용자에게는 둘 다 "이 곡을 어떤 판으로 칠까"다.
3. **넣을 때 판정이 없다.** 이미 있는 팩을 다시 넣어도, 차분만 든 압축 파일을 넣어도, 같은 곡의 다른 키음판을 넣어도 모두 새 패키지가 된다. 사용자는 무엇이 늘었는지 알 수 없다.
4. **차분이 정리를 막는다.** 다른 위치의 키음을 빌려 쓰는 차분 폴더가 있으면, 그 곡의 어느 세트도 정리하지 않는다(`key_sets::going`). 차분이 어느 세트에 기대는지 모르기 때문이다.
5. **곡에 오래 가는 id가 없다.** 곡 번호(`SongGroups`)는 스캔마다 바뀐다. bpm의 곡 id(가장 작은 채보 id의 앞자리)는 구성원이 바뀌면 바뀐다. 키음 세트 선택은 곡의 첫 위치를 키로 쓰는데, 그 위치가 정리되면 선택이 사라진다.

## 3. 원칙

- **관리 단위는 곡이다.** 패키지와 폴더는 곡의 판이 어디서 왔는지를 알려 주는 출처다.
- **판정은 B17의 함수 하나로 한다.** 새 규칙을 만들지 않는다. 게임, bpm, `bpm-gui`가 같은 판정을 쓴다.
- **사용자 파일은 지우지 않는다.** 서재 폴더(사용자가 연결한 폴더)는 옮기거나 숨기기만 한다. 지우는 것은 bpm이 설치한 패키지뿐이다. 지울 때는 사용자가 확인한다.
- **측정 먼저.** 저장 구조를 바꾸는 일(6단계)은 실제 중복 용량을 잰 뒤에 정한다.
- 개발 단계이고 사용자는 한 명이다. 옛 형식의 이전 안내는 만들지 않는다.

## 4. 설계

### 4.1 넣을 때 판정 (먼저 할 것)

`add_path`가 설치하기 전에, 받은 것의 위치마다 채보와 키음을 읽어 기존 곡과 대조한다. 대조에 필요한 기존 정보(곡별 위치, 위치별 채보, 선언 키음)는 스캔 캐시에 이미 있다. 결과는 위치마다 이 중 하나다.

| 판정 | 기준 | 기본 동작 |
|---|---|---|
| 이미 있음 | 채보가 모두 기존 위치에 있고, 키음이 그 위치와 같은 세트 | 넣지 않음 |
| 새 채보 | 기존 곡에 묶이고, 기존에 없는 채보가 있음 | 넣음. "곡 X에 채보 N개" |
| 다른 키음 세트 | 기존 곡에 묶이고, 키음이 다른 세트 | 음질 비교 결과를 보여 주고 사용자가 고름: 추가 / 기존 판 교체 / 건너뛰기 |
| 새 곡 | 어느 곡에도 묶이지 않음 | 넣음 |
| 후보 | 제목·아티스트만 같음 | 새 곡으로 넣고, 묶을지 묻는 후보로 남김 |

- `AddReport`에 이 판정을 담는다. 게임(`crates/beetle-app/src/install.rs`)과 `bpm-gui`가 각자 문장으로 바꾼다. `bpm add`는 목록으로 보여 준다.
- "이미 있음"을 정말 넣지 않을지, 묻고 넣지 않을지는 열린 질문이다(7절).
- B16(한 곡씩 풀고 넣고 지우기)과 함께 하면 좋다. 한 곡을 풀었을 때 판정하고, 넣을 것만 넣는다.

### 4.2 곡의 고정 id

판의 선택, "이 곡에 붙임", 정리 기록을 저장하려면 오래 가는 곡 id가 필요하다. 후보:

- **곡이 처음 생길 때 정한 채보 id.** 곡이 처음 생긴 순간의 가장 작은 채보 id를 곡 id로 기록하고, 그 뒤에는 바꾸지 않는다. 곡이 합쳐지면 작은 쪽 id가 남고, 다른 쪽 id는 별칭으로 남긴다. 그 채보가 지워져도 기록은 남는다.
- **위치 키(지금 키음 세트 선택이 쓰는 방식).** 간단하지만, 위치가 정리되거나 폴더 이름이 바뀌면 끊긴다.

첫째를 추천한다. 기록은 `songs.dat` 같은 MessagePack 파일 하나에 둔다(B14 방식: `format`·`version`, `write_atomic`). 곡 id → 별칭 id들, 판 선택, 붙인 차분을 담는다. `sound_sets.dat`는 여기로 옮긴다.

### 4.3 판 = 키음 세트 + 거기 딸린 채보

- 곡마다 판 목록을 둔다. 판 하나는 키음 세트 하나(같은 세트인 위치들)와, 그 위치들에 있는 채보다.
- 패키지의 설치 상태(`state_hashes`)는 판의 출처 정보가 된다. 같은 패키지의 두 상태가 같은 세트면 판 하나이고, 다르면 판 둘이다.
- 곡 메뉴의 "버전 고르기"와 "키음 세트 고르기"를 "판 고르기" 하나로 합친다. 패키지의 `active_state`는 판 선택에서 정해진다.
- 판을 고르면 그 판의 키음으로 그 곡의 모든 채보를 친다(지금 키음 세트 선택과 같음). 다른 판에만 있는 채보는 목록에 그대로 남는다.

### 4.4 차분은 곡에 붙이기

- 키음이 대부분 없는 위치(차분 폴더)는 판이 아니다. 그 곡에 붙은 채보로 다룬다.
- 차분이 어느 판의 키음에 기대는지는 B17의 빌려 쓰기 판정으로 안다. 그 판이 정리될 때 다른 판으로 대신 채울 수 있는지(같은 이름의 90%가 있는지)를 보고 정리 여부를 정한다. 지금처럼 "차분이 있으면 아무것도 정리 안 함"보다 덜 막는다.

### 4.5 정리

- 지금 정리 조건은 그대로 둔다. 나쁜 판의 채보가 남는 판에도 모두 있어야 한다.
- 거기에 "다른 판에만 있는 채보는 남기고 키음만 치우기"를 검토한다. 패키지는 안의 파일만 바꿀 수 없으므로, 판의 채보만 든 새 패키지로 다시 묶어야 한다. INV-6(결정론적 패키징)은 지켜진다. 패키지를 다시 만드는 것이라 비용이 크다. 실제로 필요한 곡이 생기면 한다(지금 서재에서는 x-Aria, End Time 2곡).

### 4.6 내용 주소 저장 (측정 뒤에 결정)

키음 파일을 내용 해시로 한 번만 저장하고, 패키지와 판은 해시를 가리키게 한다. 같은 세트를 두 번 저장하지 않는다.

- 장점: 중복이 구조적으로 없어진다. 판 교체와 정리는 가리키는 것만 바꾸면 된다.
- 비용: 저장소(`packages/`)와 읽기 경로(`PackageReader`, 로더)가 바뀐다. `.bmsp`를 하나의 파일로 주고받는 지금 모델과 어긋난다.
- 서재 폴더는 사용자 파일이라 이 저장소에 넣지 않는다. 그래서 이득은 패키지끼리의 중복에만 생긴다. 폴더 등록본과 패키지 설치본의 중복은 "이미 있음" 판정(4.1)과 정리(4.5)로 줄인다.
- 그래서 먼저 잰다: 같은 세트가 패키지끼리 몇 바이트 겹치는지, 폴더와 패키지 사이에는 몇 바이트 겹치는지. 패키지끼리 겹치는 양이 작으면 하지 않는다.

## 5. 순서

1. **측정**: 실제 서재에서 중복 용량을 잰다. 같은 세트가 패키지끼리, 폴더와 패키지 사이에 몇 바이트 겹치는지 본다. 함께, 지금 넣기에 넣었다면 4.1의 판정이 어떻게 나왔을지를 위치마다 센다. B17의 측정 도구(`crates/bms-package-manager/examples/grouping_measure.rs`)를 넓혀서 쓴다.
2. **넣을 때 판정**(4.1): `add_path`의 판정과 `AddReport`, 게임과 `bpm-gui`의 문장. B16과 함께 할지 정한다.
3. **곡 고정 id**(4.2): 기록 파일과 별칭. `sound_sets.dat`를 옮긴다.
4. **판**(4.3): 판 목록과 "판 고르기". 패키지 버전 선택을 판 선택으로 바꾼다.
5. **차분 붙이기**(4.4)와 정리 조건 완화.
6. **내용 주소 저장**(4.6): 1단계 숫자를 보고 할지 정한다. 한다면 ADR을 쓴다.

단계마다 따로 커밋한다.

## 6. 바뀌지 않는 것

- 같은 곡 판정 규칙(B17, `grouping::group`). 이 계획은 규칙을 바꾸지 않고 쓰기만 한다.
- `.bmsp` 형식과 INV-6. 6단계 전까지는 그대로다.
- 서재 폴더를 사용자 파일로 다루는 것(옮기거나 숨기기만, 지우지 않음).
- CS 디스크의 곡은 서재의 곡과 묶지 않는다.

## 7. 열린 질문

- "이미 있음"인 것을 넣으라고 받았을 때: 말없이 건너뛸지, 묻고 건너뛸지.
- "다른 키음 세트"에서 새 쪽이 확실히 나을 때: 묻지 않고 기존 판을 교체해도 되는지. B17에서는 "확실히 나은 쪽이 있으면 나쁜 쪽을 버려도 된다"고 했지만, 그것은 사용자가 확인한 뒤의 정리였다.
- 판 고르기를 곡마다 할지, 출처(패키지)마다 한 번에 할지.
- 곡 고정 id를 bpm의 곡 id(지금 짧은 해시)로도 보여 줄지.
