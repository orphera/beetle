# 스테이지 아트워크 캐시(`.cache/artworks`) 정리 계획

상태: 계획만 정리됨. 구현 보류 (2026-10-25).

## 현황

- `.cache/artworks/` 에 978개 파일, 약 574MB. 파일 하나는 약 590KB.
- 파일은 512×384 24bit 비압축 BMP(589,878 바이트, 모두 같은 크기).
- 902개가 2026-10-25에 생성됨. 곡을 볼 때마다 쌓이는 구조라 곡 수에 비례해 계속 커짐.
- 쓰기만 있고 지우는 로직이 없음 (`crates/beetle-app/src/loader/mod.rs`의 `load_stage_image`).
- 파일명은 채보 ID(`song.id.short()`). 곡이 사라져도 예전 파일이 남음(고아).
- 경로가 현재 작업 디렉터리 기준. 실행 위치에 따라 저장소 루트와 `crates/beetle-app/` 두 곳에 생김.
- `.gitignore`의 `*.cache` 패턴이 디렉터리 `.cache`도 가려서 git 상태에는 드러나지 않음.

## 작업 단계

### 1단계: 경로 통일
- 캐시 경로를 `songs.cache`와 같은 앱 데이터 디렉터리 기준으로 옮김.
- 기존 `.cache/artworks` 처리는 결정 필요: 삭제 / 그대로 두기.
- 대상: `ARTWORKS_CACHE_DIR` 사용처.

### 2단계: 고아 정리
- 스캔 완료 후 라이브러리의 곡 ID 집합을 만듦.
- 캐시 디렉터리에서 집합에 없는 `<id>.bmp`를 삭제.
- 백그라운드 작업으로 실행해 UI를 막지 않음 (AGENTS.md INV-5).
- 대상: `crates/beetle-app/src/scanner.rs`의 스캔 완료 경로.

### 3단계: 용량 상한 (LRU)
- 상한 제안: 200MB (결정 필요).
- 캐시 히트 시 `File::set_modified`로 시각 갱신. 표준 라이브러리만 사용.
- 상한 초과 시 오래된 파일부터 삭제. 기동 시 한 번, 이후 쓰기 누적 시 확인.

### 4단계 (보류): 포맷 축소
- 비압축 BMP 대신 압축 포맷 사용 시 크기가 크게 줄어듦.
- 디코더 크레이트가 필요하므로 AGENTS.md 의존성 정책을 먼저 검토.
- 1~3단계 후에도 부족할 때만 검토.

## 테스트 계획
- 고아 정리: 라이브러리에 없는 ID 파일만 삭제되는지 단위 테스트.
- LRU: 상한 초과 시 가장 오래된 파일부터 삭제되는지 임시 디렉터리로 테스트. 기존 `an_artwork_cache_write_replaces_the_file_whole_and_leaves_no_temp` 패턴을 따름.
- 경로: 실행 디렉터리를 바꿔도 같은 위치를 쓰는지 확인.

## 결정 필요
1. 기존 `.cache/artworks` 처리 (삭제 / 유지).
2. LRU 상한값 (기본 200MB).
3. 포맷 축소(4단계)를 이번 계획에 포함할지, 나중으로 미룰지.
