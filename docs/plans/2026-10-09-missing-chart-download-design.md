# 없는 곡 내려받기 설계 (2026-10-09)

난이도표에 있지만 컬렉션에 없는 곡을 bpm이 찾아 주는 기능의 설계다. 1단계(`bpm table missing`, 목록 출력)는 구현되어 있다. 이 문서는 2단계 이후를 다룬다. 구현 전 설계다.

## 1. 실제 표로 확인한 것

Satellite 표(`https://stellabms.xyz/sl/table.html`)를 `bpm table add`로 설치해 확인했다.

- 항목 2467개 전부 `url`이 있다. 상대 경로는 없고 모두 절대 주소다.
- `url`은 파일 주소가 아니라 **내려받기 페이지**인 경우가 대부분이다. 호스트별 개수:

| 호스트 | 항목 수 | 성격 |
|---|---|---|
| `manbow.nothing.sh` (http + https) | 1347 | 저작자 페이지 |
| `venue.bmssearch.net` | 194 | BMS SEARCH 이벤트 페이지 |
| `drive.google.com` | 122 | 구글 드라이브 (확인 화면 가능성) |
| `web.archive.org` | 130 | 보관본 |
| `www.dropbox.com`, `dropbox.bms.ms` | 86 | 드롭박스 |

- 즉 `url`을 받아서 zip으로 바로 풀 수 있는 항목은 드물다. 호스트마다 다른 처리가 필요하다.
- 1단계 목록 출력은 이 형식 그대로 동작했다. 없는 곡이 2467개 전부로 나온 것은 인덱스가 비어 있었기 때문이다.

## 2. 제약

- **외부 다운로드는 사용자 확인을 거친다.** 곡 파일은 저작자가 배포한 곳에서 오고, 어떤 곡을 받을지는 사용자가 정한다. 목록을 보고 한 번에 전부 받는 명령은 두지 않는다.
- **자동 판단으로 호스트를 추정하지 않는다.** 호스트별 처리(구글 드라이브 확인 페이지, 드롭박스 `dl=0`, 보관본)는 실제 응답을 보고 하나씩 추가한다.
- **무결성 확인은 풀고 나서 한다.** 난이도표 항목에 `md5`/`sha256`이 있으니, 받아 푼 차트의 ChartId가 항목과 같은지 확인한다. 같지 않으면 받은 파일을 제거하고 알린다.
- **zip 해제는 안전하게 한다.** 경로 탈출(`..`, 절대 경로)과 크기 한도를 검사한다. 기존 `bms-package-manager`의 zip 처리와 같은 규칙을 쓴다.
- **새 의존성을 추가하지 않는다** (AGENTS.md §3). `ureq`, `zip`, 기존 `HttpClient`를 쓴다.

## 3. 단계

**2a. 수동 흐름 (먼저 하는 것을 추천)**
- `bpm table missing`에 `--tsv <파일>`을 추가해 없는 곡을 파일로 내보낸다. 사용자가 그 파일을 보고 직접 받는다.
- 받은 뒤 `bpm scan`을 다시 하면 목록에서 빠진다. 새 코드 없이 기존 흐름으로 끝난다.
- 자동 다운로드 없이 목록과 확인 흐름을 검증할 수 있다.

**2b. 확인 후 내려받기 (사용자가 번호를 고르면)**
- `bpm table fetch <표> <번호 목록>`: 고른 항목만 받는다. 받기 전에 항목 이름, 호스트, 예상 파일 형태를 보여주고 확인을 받는다.
- 호스트 처리기(adapter)는 `manbow`처럼 직접 파일을 주는 곳부터 추가한다. 나머지는 페이지 주소를 열어 주기만 한다.
- 받은 zip은 임시 폴더에 풀고, 차트 ChartId를 확인한 뒤 `songs/`로 옮긴다.

**2c. 전체 자동화 (하지 않는다)**
- 표 전체를 자동으로 받는 기능은 만들지 않는다. 호스트마다 응답 형식이 다르고, 저작자가 재배포를 막아 둔 곡도 있다.

## 4. 결정이 필요한 것

1. 2a(수동 TSV 내보내기)부터 시작할지, 2b(번호를 골라 받기)까지 바로 할지.
2. 2b를 한다면 첫 호스트 처리기로 무엇을 넣을지. `manbow.nothing.sh`는 직접 파일을 주는지 아직 확인하지 않았다.
3. 받은 곡을 `songs/` 아래 어디에 둘지 (표 이름별 폴더 vs 곡 제목별 폴더).

## 5. 미확인

- `manbow.nothing.sh`, 구글 드라이브, 드롭박스 응답 형식은 아직 확인하지 않았다. 2b 전에 실제 링크를 열어 확인해야 한다.
- BMS SEARCH 이벤트 페이지(`venue.bmssearch.net`)가 파일을 직접 주는지도 확인하지 않았다. 공식 API 문서는 열지 못했다 (앞의 조사 참고).

## 6. 추가 조사: 아카이브 사이트 (2026-10-09)

더 간편하게 받을 수 있는 아카이브가 있는지 다시 찾아 보았다. 결론은 **문서화되고 살아 있는 해시 기반 다운로드 API는 찾지 못했다**는 것이다.

- **BMS Archive (BX, `bms.kyouko.moe`)**: 저장소 문서에는 `BMS_<md5>`로 곡을 찾고, `BMS2ZIP.json`으로 BMS MD5 → zip 목록을 얻고, `/zip/ZIP_<md5>.zip`으로 받는 구조가 적혀 있다. 이것이 가장 간편한 형태다. 그러나 확인 시점에 `/`, `/BMS2ZIP.json`, `/ZIP2BMS.json`, zip 경로 모두 Google Drive 폴더로 301 이동했다. 저장소는 2019년 이후 갱신이 없고 라이선스가 없다. 서비스 상태를 확인하지 못했으므로 쓰지 않는다. 운영자가 되살리거나 공식 목록을 공개하면 다시 본다.
- **BMSworld.nz**: 커뮤니티 아카이브(워드프레스)다. 2026-07에 갱신되었고 가입 없이 받을 수 있다고 소개되어 있다. 해시 조회 API나 공개 목록 형식은 확인하지 못했다. 사람이 직접 받는 출처로만 참고한다.
- **BMS Library (horieyuuka)**: 곡과 차분 묶음 파일을 나눠 제공한다(분할 압축). 개별 해시 조회는 없다.
- **BMS SEARCH**: 공식 API가 있다고 공지되어 있다(1절 참고). 검색과 목록에는 쓸 수 있지만, 파일 다운로드 API는 문서로 확인되지 않았다.

따라서 2절과 3절의 설계는 그대로 유효하다. 2a(수동 내보내기)를 먼저 하고, 호스트별 처리는 실제 응답을 본 뒤 추가한다.
