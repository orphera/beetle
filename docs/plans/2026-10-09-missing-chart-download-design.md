# 없는 곡 내려받기 설계 (2026-10-09)

난이도표에 있지만 컬렉션에 없는 곡을 bpm이 찾아 주는 기능의 설계다. 1단계(`bpm table missing`, 목록 출력)는 구현되어 있다. 이 문서는 2단계 이후를 다룬다. 구현 전 설계다.

## 1. 실제 표로 확인한 것

Satellite 표(`https://stellabms.xyz/sl/table.html`)를 `bpm table add`로 설치해 확인했다.

- 항목 2467개 전부 `url`이 있다. 상대 경로는 없고 모두 절대 주소다.
- `url`은 파일 주소가 아니라 **내려받기 페이지**인 경우가 대부분이다. 호스트별 개수:

| 호스트 | 항목 수 | 성격 |
|---|---|---|
| `manbow.nothing.sh` (http + https) | 1347 | 저작자 페이지 |
| `venue.bmssearch.net` | 194 | BMS SEARCH 이벤트 페이지 |
| `drive.google.com` | 122 | 구글 드라이브 (확인 화면 가능성) |
| `web.archive.org` | 130 | 보관본 |
| `www.dropbox.com`, `dropbox.bms.ms` | 86 | 드롭박스 |

- 즉 `url`을 받아서 zip으로 바로 풀 수 있는 항목은 드물다. 호스트마다 다른 처리가 필요하다.
- 1단계 목록 출력은 이 형식 그대로 동작했다. 없는 곡이 2467개 전부로 나온 것은 인덱스가 비어 있었기 때문이다.

## 2. 제약

- **외부 다운로드는 사용자 확인을 거친다.** 곡 파일은 저작자가 배포한 곳에서 오고, 어떤 곡을 받을지는 사용자가 정한다. 목록을 보고 한 번에 전부 받는 명령은 두지 않는다.
- **자동 판단으로 호스트를 추정하지 않는다.** 호스트별 처리(구글 드라이브 확인 페이지, 드롭박스 `dl=0`, 보관본)는 실제 응답을 보고 하나씩 추가한다.
- **무결성 확인은 풀고 나서 한다.** 난이도표 항목에 `md5`/`sha256`이 있으니, 받아 푼 차트의 ChartId가 항목과 같은지 확인한다. 같지 않으면 받은 파일을 제거하고 알린다.
- **zip 해제는 안전하게 한다.** 경로 탈출(`..`, 절대 경로)과 크기 한도를 검사한다. 기존 `bms-package-manager`의 zip 처리와 같은 규칙을 쓴다.
- **새 의존성을 추가하지 않는다** (AGENTS.md §3). `ureq`, `zip`, 기존 `HttpClient`를 쓴다.

## 3. 단계

**2a. 수동 흐름 (먼저 하는 것을 추천)**
- `bpm table missing`에 `--tsv <파일>`을 추가해 없는 곡을 파일로 내보낸다. 사용자가 그 파일을 보고 직접 받는다.
- 받은 뒤 `bpm scan`을 다시 하면 목록에서 빠진다. 새 코드 없이 기존 흐름으로 끝난다.
- 자동 다운로드 없이 목록과 확인 흐름을 검증할 수 있다.

**2b. 확인 후 내려받기 (사용자가 번호를 고르면)**
- `bpm table fetch <표> <번호 목록>`: 고른 항목만 받는다. 받기 전에 항목 이름, 호스트, 예상 파일 형태를 보여주고 확인을 받는다.
- 호스트 처리기(adapter)는 `manbow`처럼 직접 파일을 주는 곳부터 추가한다. 나머지는 페이지 주소를 열어 주기만 한다.
- 받은 zip은 임시 폴더에 풀고, 차트 ChartId를 확인한 뒤 `songs/`로 옮긴다.

**2c. 전체 자동화 (하지 않는다)**
- 표 전체를 자동으로 받는 기능은 만들지 않는다. 호스트마다 응답 형식이 다르고, 저작자가 재배포를 막아 둔 곡도 있다.

## 4. 결정이 필요한 것

1. 2a(수동 TSV 내보내기)부터 시작할지, 2b(번호를 골라 받기)까지 바로 할지.
2. 2b를 한다면 첫 호스트 처리기로 무엇을 넣을지. `manbow.nothing.sh`는 직접 파일을 주는지 아직 확인하지 않았다.
3. 받은 곡을 `songs/` 아래 어디에 둘지 (표 이름별 폴더 vs 곡 제목별 폴더).

## 5. 미확인

- `manbow.nothing.sh`, 구글 드라이브, 드롭박스 응답 형식은 아직 확인하지 않았다. 2b 전에 실제 링크를 열어 확인해야 한다.
- BMS SEARCH 이벤트 페이지(`venue.bmssearch.net`)가 파일을 직접 주는지도 확인하지 않았다. 공식 API 문서는 열지 못했다 (앞의 조사 참고).

## 6. 추가 조사: 아카이브 사이트 (2026-10-09)

더 간편하게 받을 수 있는 아카이브가 있는지 다시 찾아 보았다. 결론은 **문서화되고 살아 있는 해시 기반 다운로드 API는 찾지 못했다**는 것이다.

- **BMS Archive (BX, `bms.kyouko.moe`)**: 저장소 문서에는 `BMS_<md5>`로 곡을 찾고, `BMS2ZIP.json`으로 BMS MD5 → zip 목록을 얻고, `/zip/ZIP_<md5>.zip`으로 받는 구조가 적혀 있다. 이것이 가장 간편한 형태다. 그러나 확인 시점에 `/`, `/BMS2ZIP.json`, `/ZIP2BMS.json`, zip 경로 모두 Google Drive 폴더로 301 이동했다. 저장소는 2019년 이후 갱신이 없고 라이선스가 없다. 서비스 상태를 확인하지 못했으므로 쓰지 않는다. 운영자가 되살리거나 공식 목록을 공개하면 다시 본다.
- **BMSworld.nz**: 커뮤니티 아카이브(워드프레스)다. 2026-07에 갱신되었고 가입 없이 받을 수 있다고 소개되어 있다. 해시 조회 API나 공개 목록 형식은 확인하지 못했다. 사람이 직접 받는 출처로만 참고한다.
- **BMS Library (horieyuuka)**: 곡과 차분 묶음 파일을 나눠 제공한다(분할 압축). 개별 해시 조회는 없다.
- **BMS SEARCH**: 공식 API가 있다고 공지되어 있다(1절 참고). 검색과 목록에는 쓸 수 있지만, 파일 다운로드 API는 문서로 확인되지 않았다.

따라서 2절과 3절의 설계는 그대로 유효하다. 2a(수동 내보내기)를 먼저 하고, 호스트별 처리는 실제 응답을 본 뒤 추가한다.

### 6.1 BMS-Community/resources 확인 (2026-10-09)

[BMS-Community/resources](https://github.com/BMS-Community/resources)는 링크 목록 저장소다. API나 해시 색인은 없다. 확인한 내용은 다음과 같다.

- 표 목록 섹션은 표의 주소만 나열한다(Satellite, Stella, Stardust 등). `bpm table add`로 설치할 주소를 찾는 데는 쓸 수 있다.
- "BMS uploader Mirror"(`darksabun.club/mirror/absolute/`)는 2015년 이후 갱신이 없고, 페이지에도 "현재 다운로드만"이라고 적혀 있다. 해시 조회는 없다.
- "BMS uploader Mirror (alternative)"(`mirror.lovelyrad.io`)는 정적 디렉터리 목록이고, 2021년 이후 파일이 없는 폴더(`bof/`, `longnote/`, `turntable/`, `uploader/`)만 있다.
- "Packages for all the major difficulty tables"는 `bms.kyouko.moe`를 가리키는데, 6절에서 확인한 대로 Google Drive로 이동된다.
- 나머지 대부분은 Google Drive, Dropbox, OneDrive, pastebin 링크다. 자동 접근에 맞지 않는다.

결론: 이 저장소에서도 해시로 곡을 찾아 받는 자동화 경로는 나오지 않았다. 2a(수동 내보내기)를 진행하는 방향은 바뀌지 않는다.

### 6.2 IR 해시 조회와 실제 받기 확인 (2026-10-10)

IR 사이트를 확인한 결과, 해시로 곡을 찾는 경로가 있었다. 다만 사이트마다 사정이 다르다.

- **Mocha-Repository** (`mocha-repository.info`): `song.php?sha256=<64 hex>`로 차트를 바로 조회할 수 있다. 제목, 레벨, 노트 수, BPM, 다른 IR 목록이 나온다. 목록 검색(`songs.php`)에는 해시 칸이 없고 제목과 아티스트로만 찾는다. 확인한 4개 차트(`race` 14키 ANOTHER/HYPER/NORMAL/BEGINNER 계열)가 모두 조회되었다. 조회 결과에 파일 링크는 없다.
- **Stella IR** (`ir.stellabms.xyz/charts/<32 hex>`): MD5로 차트 페이지가 있고, 페이지에 MD5, 레벨, BPM, 다운로드 링크(보관본과 차분 zip)가 나온다. 브라우저로는 자동화 방지 화면 때문에 열리지 않았다. 일반 조회 도구로 읽었고, 확인 화면은 우회하지 않았다. 이 사이트는 파일을 직접 주지 않고 링크만 알려 준다.
- **MinIR** (`gaftalk.com/minir/`): 자동화 방지 화면(403)이라 확인하지 못했다.
- **CitrusIR** (`citrus-ir.iidx.app`): 도메인을 찾지 못했다.
- **LR2IR**: 추정 주소(`dream-pro.info`)가 DNS에서 찾아지지 않았다. 현재 주소를 확인하지 못했다.

실제로 받아 검증한 사례 (Qualia [Quantia], 7KEYS ☆12, Junk, MD5 `1ab0ea1a6d3d28f7b4ce2ad366edc38d`):
- Stella IR 페이지의 보관본 링크(`web.archive.org`, `junk_qualia.rar`, 약 9.0 MB)는 MD5가 맞지 않았다. 차트 5개(7a/7b/7h, 14e/14k) 모두 해시가 달랐다. 이 보관본은 찾는 판본이 아니었다.
- 같은 페이지의 차분 링크(`bms.hexlataia.xyz/mirror/gnqg-upload/02646.zip`, 9,490 bytes)에는 `.bms` 한 개가 있었고 MD5와 SHA-256이 모두 찾는 값과 일치했다.
- 두 파일은 압축을 풀지 않고 7-Zip으로 항목을 읽어 해시만 계산했다.

이 결과로 확인된 것:
- 해시 하나로 IR 페이지를 찾고, 그 페이지의 링크를 받아, 받은 파일의 해시로 맞는지 확인하는 흐름은 가능하다. 이것은 2b(사용자가 고른 항목을 하나씩 받기)와 맞는다.
- 링크는 보관본이나 개인 호스팅이라 죽었거나 다른 판본일 수 있다. 받은 뒤 해시를 확인하는 단계가 반드시 필요하다.
- 일괄 자동 다운로드는 여전히 만들지 않는다 (2c).
- IR 사이트에 자동화 방지 화면이 있으면 우회하지 않는다. 그 경우 사용자가 직접 확인하고 알려 주는 방식으로 간다.

## 7. 구현 상태 (2026-10-09)

- `bpm table missing`: 항목에 번호(`#n`)를 붙였다. 온전한 사본(키음이 모두 옆에 있는 사본)이 있는 곡만 소유로 센다. 사본은 있지만 키음이 빠진 곡은 `[body needed]`로 표시하고 소유로 세지 않는다.
- `bpm table fetch <표> <#>... [--yes]`: `stellabms.xyz/upload/` 직접 zip 링크만 받는다. 받기 전에 묻는다. zip 안에 해시가 표 항목과 같은 차트가 있을 때만 `songs/<표>/<#>`에 보관한다. 보관 후 본체 페이지 주소를 함께 보여 준다.
- 검증: 실제 Satellite 표 #32(BloddoN [EX_A], `003047.zip`, 52 KB)로 받기, 보관, scan, 상태 표시까지 확인했다. zip에는 .bms 한 개만 있었고 #WAV 816개의 본체가 없어서 `[body needed]`로 나왔다.

의도적으로 하지 않은 것: 본체 자동 다운로드, manbow 페이지 파싱, 차분을 본체 폴더로 복사·이동, 게임이 다른 폴더의 키음을 찾는 기능, 차분과 본체의 자동 연결 규칙. 본체 짝짓기는 Opus 상담 결과대로 사용자가 본체 폴더를 등록하면 기존 scan의 키음 이름 비교에 맡긴다.

미확인: 차분의 키음이 본체 키음의 부분집합인지. 본체를 받아 보기 전에는 확인할 수 없다.

### 7.1 본체와 차분 흐름 (2026-10-09 추가)

- `bpm table fetch <표> <#>... --body`: 항목의 본체 페이지(`url`)를 브라우저로 연다. 받지 않는다. http(s) 주소만 연다. Windows에서는 `rundll32`로 연다.
- `bpm table fetch <표> <#>... --into <폴더>`: 차분 zip을 받아, 해시가 맞는 차트를 포함한 zip 내용을 이미 있는 `<폴더>`에 복사한다. 같은 이름의 파일은 덮어쓰지 않고 건너뛰며, 결과에 복사 수와 건너뛴 수를 보인다.
- 확인 흐름: Satellite #32(BloddoN [EX_A])의 본체 `BloddoN_ogg.rar`(RAR5, 약 45.6 MB, `.ogg` 875개)을 7-Zip으로 풀고, `--into`로 차분 `003047.zip`을 본체 폴더에 넣었다. 본체 폴더만 등록한 임시 색인에서 #32는 소유로 집계되고, `[body needed]`는 0이었다.
- 사용자 `library.dat`은 바꾸지 않았다. 본체 폴더를 쓰려면 `bpm library add`로 등록하고 `bpm scan`을 해야 한다.
- 본체를 자동으로 받는 공개 소스는 찾지 못했다. bmz-player는 사용자가 설정하는 IPFS 노드와 HTTP 템플릿을 쓰고, 둘 다 기본값이 꺼져 있다. Qwilight는 링크를 브라우저로 여는 방식이다.
