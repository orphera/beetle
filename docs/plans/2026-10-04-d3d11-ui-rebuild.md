# D3D11 단일 렌더러 기반 UI 재구축 (2026-10-04)

## 배경

목표는 상용 리듬게임 수준의 UI다. 2026-10-03의 두 라운드
(`2026-10-03-gameplay-hud-redesign.md`, `2026-10-03-pulse-redesign.md`)는
화면 단위 패치를 반복했지만, 아래의 구조적 원인 때문에 결과물이 계속
아마추어처럼 보였다. 이번 계획은 화면을 더 고치기 전에 그 밑바닥부터
교체한다.

### 진단 (2026-10-04 코드 기준)

1. **텍스트**: `fontdue`로 래스터한 글리프를 옛 비트맵 폰트의 고정 셀
   (5×7 × 정수 배율)에 다운샘플해 끼워 넣는다
   (`crates/beetle-render/src/bitmap_font/mod.rs`). 글자 크기가 7px 단위
   계단으로만 존재하고, 사실상 고정폭이며 커닝이 없다. 그 아래로 손 그림
   비트맵 ASCII/한글/가나, `bold_digits`, GDI 폴백까지 경로가 4~5개 겹쳐 있다.
2. **렌더 경로 이중화 + 메뉴의 CPU 렌더링**: 게임플레이는
   `gameplay.rs`(CPU) / `gameplay_gpu.rs`(D3D11) 두 벌이다. 나머지 화면은
   D3D11이 켜져 있어도 CPU로 그린 전체 프레임을 매 프레임 텍스처로
   업로드한다(`crates/beetle-app/src/main.rs`의 `d3d11_frame_texture`).
   저사양에서 60 FPS 미달의 직접 원인.
3. **배칭 제약**: UI 사각형(텍스처 없음)과 텍스트(폰트 아틀라스)가 다른
   텍스처라 GPU 경로에서는 "사각형 전부 → 텍스트 전부" 순서를 강제해야
   했고, 그 때문에 레이아웃이 깎였다.
4. **토큰·레이아웃 체계 부재**: `screens/`에 `ColorRgba::new` 직접 색상이
   약 250곳, `ColorToken` 사용은 약 40곳. 좌표는 `56.0 * s` 류 매직 넘버
   약 450곳.
5. **에셋 부재**: 모든 비주얼을 사각형/그라디언트/삼각형 조합으로만 그린다.

## 결정 사항

- D3D11 단일 렌더러, 소프트웨어 렌더러 폐지, WARP 폴백, Windows 전용
  (docs/DECISIONS.md ADR-026).
- 디자이너 에셋 없음 → **기본 스킨은 코드로 생성**해 시작 시 아틀라스에 굽는다.
  외부 파일·바이너리 내장 이미지 없음.
- LR2 공개 스킨은 기본 스킨으로 쓰지 않는다(재배포 라이선스 제각각,
  `.lr2skin` 호환 레이어 비용, 2000년대 룩). 사용자가 직접 넣어 쓰는
  외부 스킨 로더는 별도 마일스톤 후보로 남긴다.

## 단계

### P0 — 결정 기록 + 장치 생성 강건화 ✅
- [x] ADR-026 추가, ADR-004/005/019 대체, ADR-018 일부 대체 표기
- [x] AGENTS.md INV-4 / 의존성 / 모듈 설명 갱신
- [x] `D3d11Backend::new`: 기능 레벨 11_0 → 10_1 → 10_0, HARDWARE 실패 시 WARP

### P1 — 공용 Canvas API ✅
- [x] `crates/beetle-render/src/canvas/`: 그리기를 기록만 하고 `end`에서 일괄
  제출하는 즉시 모드 API. 그리는 동안 백엔드 접근 없음.
  - 단색 / 꼭짓점별 색(그라디언트) 사각형, 볼록 사변형·삼각형, 선, 테두리
  - 아틀라스 스프라이트, 부분 스프라이트, 9-slice, 외부 텍스처(재킷/BGA)
  - 클립 스택(Sutherland–Hodgman, UV·색 보간) — 백엔드 시저 불필요
- [x] **Premultiplied alpha 전면 채택** (`BlendMode::Premultiplied`). 가산 광원은
  alpha=0 색으로 표현(`set_additive`)하므로 글로우/빔이 배치를 끊지 않는다.
- [x] `UiAtlas`: 2048² 페이지(최대 8장), 셸프 패킹, 1px 투명 거터,
  dirty 페이지만 업로드. 단색도 아틀라스의 흰 텍셀을 샘플 → 단색·스프라이트·
  글리프가 한 배치. 배치는 텍스처가 실제로 바뀔 때(외부 이미지)와 백엔드
  버퍼 한계(8192 정점 / 12288 인덱스)에서만 나뉜다.
- [x] 셰이더 사전 컴파일: `crates/beetle-render/shaders/ui2d.hlsl` →
  `scripts/compile-shaders.ps1`(fxc) → `shaders/compiled/*.cso` 내장.
  소스를 고치고 재컴파일을 잊으면 `compiled_shaders_match_source` 테스트가 실패.
- [x] `GpuBackend::capture_frame`(D3D11 백버퍼 리드백) +
  `BEETLE_D3D_WARP=1`로 WARP 강제.
- [x] 실기 테스트 `crates/beetle-render/tests/d3d11_canvas.rs`: 숨김 창에
  테스트 패턴을 그려 하드웨어·WARP 양쪽에서 픽셀값 검증(전체 패턴 1 드로우콜),
  캡처는 `target/canvas-test-*.bmp`.
- 변경: "게임플레이 화면을 Canvas로 옮겨 드로우콜 유지" 검증은 P4로 이동.
  텍스트가 아직 별도 `FontAtlas` 텍스처라 지금 옮기면 오히려 드로우콜이 는다.
- 측정: `beetle-app.exe` 릴리스 3,152,384 B (2026-10-04, 폰트 에셋 포함).

### P2 — 텍스트 엔진 ✅
- [x] `crates/beetle-render/src/text/`: `TextEngine` + `TextStyle`(크기 px, 굵기,
  색, 자간). 요청 크기를 정수 px로 반올림해 래스터 → Canvas 공유 아틀라스에
  캐시. 글리프는 정수 픽셀에 스냅되어 텍셀:픽셀 1:1로 선명하다.
- [x] 글자별 advance + 커닝, 베이스라인 기준 그리기, `draw_in`(정렬 + 대문자
  높이 기준 광학적 수직 중앙), `fit`(말줄임 `...`), `metrics`.
  `draw_scaled`는 애니메이션용으로 한 크기만 캐시하고 쿼드를 확대한다.
- [x] **라틴 폰트 교체**: 기존 UI의 라틴 문자는 코딩용 고정폭 폰트(JetBrains
  Mono)였다. 내장 Noto Sans KR 서브셋에 이미 있던 비례폭 라틴(숫자는 고정폭
  tabular라 점수가 흔들리지 않음)을 쓴다.
- [x] **커닝 복구**: fontdue는 구형 `kern` 테이블만 읽는데 Noto는 GPOS 커닝만
  있어 커닝이 0이었다. `scripts/add-latin-kern.py`로 ASCII 882쌍을 `kern`
  테이블로 구워 넣었다(+5 KB).
- [x] 굵기: 내장 폰트는 합성 볼드(커버리지 우/상 방향 팽창, em의 4%),
  GDI 폴백은 FW_BOLD.
- [x] 폴백 체인: Noto KR(라틴·한글) → Noto JP(가나·상용한자·CJK 구두점;
  CJK 범위는 JP 우선) → **GDI 글리프 단위 래스터**(Yu Gothic → Meiryo →
  MS Gothic → 맑은 고딕 → YaHei → SimSun, `GetGlyphIndicesW`로 실제 보유
  확인) → 빈 상자. 시스템 CJK 폰트를 fontdue로 통째로 읽으면 300~400 ms라
  채택하지 않았다.
- [x] 실기 테스트 `crates/beetle-render/tests/d3d11_text.rs`(WARP): 크기별
  견본 + 점수 레이아웃 + 패널 위 말줄임을 1 드로우콜로 그리고
  `target/text-specimen.bmp`로 저장.
- 변경: 구 `bitmap_font/` 삭제는 P4로 이동 — 소프트웨어 렌더러 화면들이
  아직 사용 중이다. 폰트 바이트는 새 엔진과 공유하도록 바꿔 중복 내장은 없다.
- 남은 과제: 가나·한자(JP 서브셋)가 한글보다 약간 굵다. 기호(… · ★ → ×)가
  서브셋에 없어 GDI로 그려지므로 일본어 폰트 모양이 섞인다. 원본 폰트로
  서브셋을 다시 만들 때 해결한다.

### P3 — 코드 생성 기본 스킨 ✅
- [x] `crates/beetle-render/src/art/`: SDF(부호 거리 함수)로 계산한 스프라이트를
  현재 UI 배율로 생성해 공유 아틀라스에 굽는다. 이미지 파일 0개.
  - 둥근 패널 4/8/16px + 외곽선, 가우시안 드롭섀도(`Halo`), 컷 코너 패널 + 외곽선
  - 글로우, 키 빔, 노트 헤드(명도 베벨, 색은 틴트) + 가산 광택, 롱노트 몸통
  - 히트 링, 스파크, 크로스 플레어, 그레인 타일, 비네팅
  - 아이콘: 재생, 좌/우 셰브런, 별, 체크, 점
- [x] 스왑체인에 MSAA가 없으므로 **대각선·곡선 가장자리는 반드시 이 스프라이트로**
  그린다(`Canvas::fill_quad` 폴리곤은 계단 현상). 모듈 문서에 규칙 명시.
- [x] `Ui` 컨텍스트(`ui.rs`) = Canvas + TextEngine + Skin. 배율이 바뀌면
  아틀라스를 비우고 스킨·글리프를 다시 생성(공간 누수 없음 — 테스트로 확인).
- [x] Canvas: `nine_slice_hgradient`(모양을 따라가는 그라디언트 9-slice),
  `nine` / `nine_hgradient` / `halo` / `tile` / `sprite_centered` 헬퍼.
- [x] 실기 쇼케이스 `crates/beetle-render/tests/d3d11_skin.rs`(WARP): 선곡·게임플레이
  구성 화면을 각각 **1 드로우콜**로 렌더링, `target/skin-{menu,gameplay}.bmp`.
  이 구성이 P4 화면 이식의 시각 기준이다.
- 측정(릴리스): `Ui::new`(폰트 파싱 + 스킨 생성) 96 ms. 0.75x~3x 배율 모두
  아틀라스 1페이지에 들어간다.

### P4 — 화면 이식 (한 번에 한 화면)
- 순서: Gameplay → SongSelect → Result → KeyConfig/모달 → Loading.
- 이식 시 규칙 강제: 색은 토큰만, 좌표는 간격 스케일(4/8/12/16/24/32/48)과
  Rect 분할 헬퍼로만. `screens/`에서 `ColorRgba::new`를 금지하는 테스트 추가.
- 마지막 화면 이식 후 `SoftwareRenderer`, `backend/soft.rs`, `gameplay.rs`,
  `components/`의 tiny-skia 경로, beetle-app의 softbuffer 의존성 삭제.
