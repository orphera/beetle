# 상용급 프레젠테이션 계획

## 결론

현재 빌드는 일관되고 깔끔한 **도구**다(토큰, 타이포, 1-드로우콜 규율, 정보 구조). 부족한 것은 게임처럼 느끼게 하는 층이다: **소리(메뉴 효과음 0개), 움직임(정적 배경, 0.2 s 페이드뿐인 전환), 연출, 정체성(타이틀 없음), 컨트롤러, 영어 UI.**

코드만으로는 $49에 닿지 않는다. 그 가격의 리듬게임은 UI가 아니라 **콘텐츠**(곡, 재킷, BGA, 키 비주얼)를 판다. 현실적인 목표는 "프레젠테이션이 상용급처럼 느껴지는 플레이어"이며, 판매하려면 최소 콘텐츠(아래 완료 정의 10항)가 필요하다. 콘텐츠 없이는 현실적인 가격대가 무료~$15다.

## 제약 안에서 쓰는 방법

- **효과음**: 부팅 때 가산 합성(사인/노이즈/엔벨로프)으로 PCM을 만든다. 수 KB.
- **배경·재킷 대체 이미지·노트 스프라이트**: SDF·파티클·해시 기반 팔레트로 코드 생성.
- **셰이더**: 오프라인 컴파일한 `.cso` 내장은 ADR-026과 맞는다. 블러는 곡이 바뀔 때 한 번 계산해 캐시(WARP 60 fps 유지).
- **크기**: 지금 3.16 MB. 위 항목은 합쳐 +100~200 KB. 중국어는 폰트 서브셋이 MB 단위라 보류.
- **코드로 불가능**: 로고·키 비주얼 일러스트, 메뉴 BGM(절차적 BGM은 싸구려로 들림), 캐릭터. 우회: 라이브러리 곡 프리뷰를 메뉴 음악으로, 선택형 사용자 스킨 폴더.

## 갭 요약

| 영역 | 등급 | 내용 |
|---|---|---|
| 전역 | blocking | 메뉴 소리 없음 |
| 전역 | big | 정적 배경, 컷 위주 전환, 컨트롤러 없음, 한국어만, 타이틀 없음 |
| 선곡 | big | 행에 재킷 없음, 모든 곡 대체 이미지가 같아 보임, 정수 인덱스 스크롤 |
| 플레이 | big | 평평한 노트, 판정·콤보 타이포, 좁은 플레이필드와 디버그 같은 HUD, 카운트다운·FC·FAILED 연출 미검증 |
| 결과 | big | 소리·스탬프 연출 없음 |
| 설정 | big | 볼륨 분리, 비주얼 오프셋, 언어, 플래시 감소 등 없음 |
| 옵션 모달·키 설정·로딩 | small | 구조는 상용급. 소리와 미세 모션만 |

## P0 — 소리와 움직임 (약 1–2주)

1. **UI 효과음 합성** (M): `beetle-audio/src/sfx.rs`, `preview.rs`를 메뉴 오디오 스트림으로 일반화, `SampleTrigger`로 재생. 호출은 `handlers/*` 공용 함수에서. 위험: 게임플레이 `AudioEngine`과 장치 공유 — Loading 진입 시 메뉴 스트림을 닫는다(INV-1, INV-2 유지). 검증: PCM 피크·길이 테스트, 귀로 확인, 볼륨 0 무음.
2. **프리뷰** (S): 200–300 ms 지연 시작, 페이드, 결정 시 덕킹.
3. **선곡 모션** (M): `scroll`을 f32로 두고 이징, 선택 행 확장, 상세 패널 크로스페이드. 검증: t=0/0.08/0.3 s 캡처.
4. **화면 전환** (S–M): `transition.rs`에 셔터/와이프. Loading→Gameplay도 포함(READY 전 렌더 전용, 판정·클럭 불변).
5. **살아 있는 배경** (S): `widgets::backdrop`에 시간 인자, 재킷 색 블롭·파티클. `lite`(WARP)에서는 정적.
6. **잔버그** (S): 로딩 `0.1s` 제거, 자동 플레이 시 `첫 플레이` 태그 숨김.

## P1 — 플레이 손맛 (약 2–3주)

1. **노트·판정 스킨 2판** (M–L): 림·베벨·하이라이트, LN 흐르는 몸통, 비트 펄스 판정선(오디오 클럭 기준, INV-1), 아웃라인 판정·콤보 글리프.
2. **레이아웃** (M): 판정 카운트 표 축소, BGA 확대 또는 어두운 전체 배경 옵션.
3. **시작·종료 연출** (M): 카운트다운→GO, FULL COMBO·CLEAR·FAILED 컷신 + 징글. 실제 앱에서 FC·FAILED를 확인한다.
4. **설정 확장** (M): BGM·키음·SFX 볼륨(믹서 버스 게인, 락프리), 비주얼 오프셋(렌더 위치만), 노트 크기, 판정 표시 위치, 플래시 감소.

## P2 — 첫인상과 정체성 (약 2–3주)

1. **결과 단계 공개** (M): 카운트 틱 → 랭크 스탬프(플래시·흔들림) → 램프 → 신기록.
2. **선곡 행 재킷** (M–L): STAGEFILE/BANNER를 워커에서 디코드(INV-5), 아틀라스 LRU, 곡별 절차 대체 이미지. 위험: 아틀라스 8페이지 한도, 스크롤 중 디코드 폭주(요청 큐 상한).
3. **블러 렌더 타깃 패스** (M): 다운샘플 + 가우시안 `.cso`. 드로우콜 테스트 예외를 명시.
4. **최소 타이틀/어트랙트** (M): 워드마크 애니메이션, ENTER, 프리뷰 루프, 한 키로 건너뛰기.

## P3 — 시장 요건 (약 3–4주)

1. **현지화** (M): `strings.rs`를 언어별 표로, 언어 설정, 글자 범위 테스트를 언어별로. 영어 필수, 일본어 다음.
2. **컨트롤러** (L): `raw_input.rs`에 HID(IIDX 컨트롤러·턴테이블), 메뉴용 XInput은 `xinput1_4.dll` 직접 FFI, 메뉴 액션 계층. 실기 확인 필요.
3. **디스플레이** (S–M): 보더리스, 울트라와이드, 고주사율.
4. **접근성** (S–M): UI 배율, 흔들림·플래시 끄기, 고대비 노트.

## P4 — 콘텐츠와 확장

1. 선택형 사용자 스킨 폴더(PNG가 아틀라스 영역을, WAV가 SFX를 덮어씀. 기본값은 코드 생성).
2. 코드 생성 튜토리얼 차트(첫 실행 연습 + 오프셋 측정).
3. 번들 콘텐츠(코드 밖, 아래 참고).

## 결정이 필요한 것과 권고

| 결정 | 권고 |
|---|---|
| 메뉴 SFX | 예, 코드 합성 |
| 메뉴 BGM | 합성은 아니오. 프리뷰를 메뉴 음악으로, 판매용은 작곡 루프 1–2개를 콘텐츠로 확보 |
| STAGEFILE/BANNER 재킷 | 예, 행 썸네일로 확장 |
| 컨트롤러 | 예. HID + 메뉴용 XInput |
| 스킨 시스템 | 사용자 폴더 덮어쓰기만 |
| 타이틀 화면 | 예, 최소형 (U6 결정을 뒤집는 것) |
| exe에 에셋 내장 | 아니오. 판매 콘텐츠는 별도 콘텐츠 팩 |
| 크기 예산 | +200 KB 허용, AGENTS.md의 1 MB 목표를 현실 수치로 갱신 |
| 언어 | 영어 필수, 일본어 다음, 중국어 보류 |

## 하지 않는 것

LR2/beatoraja 스킨 호환, 3D·Live2D·캐릭터, 절차적 작곡, 메뉴 영상 배경, 매 프레임 전체화면 포스트이펙트, 디자인 토큰 체계 재작성, 결정적 로딩 진행률, 업적·온라인 랭킹(코어 연출보다 먼저 하지 않음), 테마 옵션 남발.

## 판매 준비 완료 정의

1. 모든 메뉴 조작에 소리, 결과·클리어·실패에 징글. 메뉴에서 무음인 순간이 없음.
2. 화면 전환에 컷 0개, 리스트·패널·모달 모두 이징. 하드웨어와 WARP 모두 60 fps.
3. 행 재킷, 재킷 없는 곡도 서로 구별되는 대체 이미지.
4. 카운트다운, FC·CLEAR·FAILED 연출을 실제 앱에서 확인. 노트·판정 스킨 2판.
5. 볼륨 3분리, 비주얼·판정 오프셋, 언어, 플래시 감소, 보더리스.
6. 영어 UI 100%.
7. HID 컨트롤러와 XInput 메뉴 조작을 실기로 검증.
8. 타이틀 → 튜토리얼/오프셋 → 첫 플레이까지 설명서 없이 3분 안.
9. 크기·성능 수치를 문서에 기록.
10. **최소 콘텐츠**: 로고 + 키 비주얼 1장, 재배포 허락받은 곡 20–40개(재킷·BGA 포함), 메뉴 BGM 루프 1–2개, 트레일러.

## P0 결과 (2026-10-17)

P0-1~6을 모두 구현했고 Opus 리뷰 뒤 지적 사항(클릭 가능한 잘린 행, 상세 패널 깜빡임, 시작음 누락, 셔터 컷, 프리뷰 타이머 덮어쓰기, `Canvas::line` 감김 방향 등)을 고쳤다. 릴리스 크기: `beetle-app.exe` 3,175,424 B(+16 KB). 소리와 실제 움직임은 사람이 직접 확인해야 한다(에이전트는 들을 수도, 라이브 애니메이션을 볼 수도 없었다).
