## 1. CS Disc 곡 길이가 실제보다 짧음
- 증상: 특히 변속곡(BPM이 바뀌는 곡)에서 심함.
- 가설: 길이 계산이 BPM 변화를 반영하지 않거나, 변속 구간을 한 번만 세는 것으로 보임.
- 관련: `crates/cs-disc/`, 곡 길이 계산 경로.
- 확인 필요: CS Disc에만 있는지, 일반 BMS에도 있는지.
- 조사 결과(2026-10-25, 코드 확인):
  - 곡 길이는 `TimingModel::total_duration_seconds` ([crates/beetle-core/src/timing.rs:337](crates/beetle-core/src/timing.rs:337))가 정함. 일반 노트와 BGM 노트의 **시작 시각** 중 최댓값만 본다.
  - `gameplay.rs:263`이 이 값을 `song_end_time`에 넣고, 종료 판정(`audio_time >= song_end_time + 1.5`)과 플레이 화면 시계에 쓴다.
  - 그래서 곡의 **오디오 길이(마지막 BGM/키음 샘플의 끝)** 가 아니라 **마지막 노트/BGM 시작 시각**이 곡 길이가 된다. 오디오가 끝나기 전에 시계가 끝나는 것과 같은 현상.
  - CS Disc 곡은 BGM 스트림을 차트 시작에 한 번 재생하는 음이므로 시작 시각만 잡히고 스트림 길이가 빠짐. 변속곡에서 더 두드러지는지는 실제 디스크로 확인 필요.
  - 저장소의 실디스크 테스트(`crates/cs-disc/tests/real_discs.rs`)는 로컬 디스크 이미지가 필요해 이 환경에서는 실행하지 못함.
- 수정 방향(제안): 곡 길이를 "마지막 노트 시각"과 "마지막 BGM/키음 샘플의 시작 시각 + 샘플 길이" 중 큰 값으로 계산. 샘플 길이는 로딩 시점에 이미 디코딩된 `SampleBank`에서 얻음(INV-3, 재생 중 디코딩 없음).

## 2. BPM 표시가 현재 BPM을 반영하지 않음
- 증상: 플레이 중 BPM 표시가 변속 후에도 시작 BPM에 머묾.
- 원인(코드 확인, 2026-10-25): `song_block` 이 `header.bpm`(차트 헤더의 시작 BPM)을 그대로 씀. [play.rs:1333](crates/beetle-render/src/screens/play.rs:1333). 헤더 값은 로딩 때 한 번 정해지는 값이라 재생 중 바뀌지 않음.
- 이미 있는 자료: `PlayFrame` 에 `timing`(TimingModel)과 `audio_time` 이 있음. 구간 목록 `segments` 의 `bpm` 과 `start_time_seconds` 로 현재 BPM을 구할 수 있음. `bpm_stats` 는 최소·최대·주된 BPM을 이미 계산함([timing.rs:299](crates/beetle-core/src/timing.rs:299)).
- 수정 방향(제안):
  - 현재 BPM = `audio_time` 이 속한 구간의 `bpm`. 정지(STOP) 중에는 직전 BPM 유지.
  - 변속곡은 "현재 BPM (최소–최대)" 형태로 표시. 일반 곡은 현재 값 하나만 표시.
  - 판정·노트 위치는 건드리지 않음(INV-1). 표시만 바꿈.
- 확인 필요: 시작 시 헤더 BPM이 쓰이는 다른 곳(선곡 정렬, 곡 정보)은 그대로 둘지 결정.
- 처리(2026-10-25): 구현 완료, 검증 전.
  - `TimingModel::bpm_at_time` 추가([timing.rs](crates/beetle-core/src/timing.rs)). 테스트 추가.
  - 플레이 화면 부제를 "아티스트 / BPM 현재값 (최소-최대)"로 바꿈. 최소와 최대가 같으면 현재값만 표시([play.rs](crates/beetle-render/src/screens/play.rs)).
  - 검증: `beetle-core` timing 테스트 10개, `beetle-render` play 테스트 48개 통과.
  - 미검증: 실제 변속곡을 플레이 화면에서 직접 확인하지 않음. 범위 값은 곡 길이(`song_length`)까지 기준이라 항목 1번이 바뀌면 범위도 달라짐.
  - 참고: 범위 계산이 프레임마다 실행됨. 문제가 되면 플레이 시작 때 한 번만 계산하도록 옮길 것.

## 3. 판정/콤보 표시가 시간이 지나도 그대로 있음
- 증상: 판정 문구와 콤보 숫자가 사라지지 않고 계속 보임.
- 관련: 판정 표시 수명(타이머) 처리. 렌더 측 `dt` 대신 오디오 클럭 기준으로 만료시켜야 할 가능성 (INV-1).

## 4. 선곡창 제목에서 `( ) [ ]` 전부 삭제
- 증상: 괄호 안 내용이 통째로 사라짐.
- 원인: canonicalize가 괄호를 무조건 지움.
- 올바른 방식: 같은 폴더의 BMS 제목들을 모아 공통 부분만 떼어냄. 괄호 안 내용이 곡마다 다르면 보존.
- 관련: 곡 제목 정규화 함수 (`crates/beetle-core/` 또는 `scanner.rs` 근처에서 확인 필요).

## 5. `-` 로 구분된 난이도를 구분하지 못함
- 증상: 제목의 ` - BEGINNER` 같은 난이도 표기를 인식하지 못함.
- 원인: 공통 부분 추출 시 `-` 구분자를 다루지 않음.
- 함께 처리: 항목 4와 같은 함수에서 해결.

## 7. RemyWiki 메타데이터 배포 가능 여부
- 조사 결과: RemyWiki 이용약관 페이지(`remywiki.com/Special:Terms_of_Use`)가 봇 확인 화면에 막혀 본문을 읽지 못함. 우회하지 않음.
- 확인한 페이지:
  - `RemyWiki:General_disclaimer`: 정보의 정확성을 보장하지 않으며, 위키는 정보에 대한 저작권을 주장하지 않는다고 적혀 있음.
  - `RemyWiki:About`: 정보는 KONAMI 공식 사이트, 사운드트랙, BEMANIWiki 2nd 등 외부 출처에서 모았다고 적혀 있음. 재배포 허가 문구는 없음.
- 판단: 명시적 라이선스(CC 등)는 없음. "저작권을 주장하지 않는다"는 문구는 재배포 허락으로 보기 어려움. 원출처(KONAMI, BEMANIWiki) 권리가 남아 있을 수 있음.
- 결정(2026-10-25):
  - 메타데이터 데이터는 배포물(바이너리, 설치 패키지)에 넣지 않음.
  - 사용자가 실행할 때 필요한 만큼만 조회하고, 조회한 항목마다 RemyWiki 출처 링크를 표시.
  - 대량 수집, 일괄 다운로드는 하지 않음. 요청 간격을 두어 위키에 부담을 주지 않음.
  - 조회 스크립트(코드)는 배포해도 됨. 데이터를 담지 않으므로 데이터 배포보다 위험이 작다고 판단. 다만 스크립트가 자동 조회를 하므로 위 조건을 기본값으로 둠.
  - 필요하면 운영자(sysop)에게 허가를 문의.
- 이 판단은 법률 자문이 아님. 배포 전에는 법률 검토를 권장.
