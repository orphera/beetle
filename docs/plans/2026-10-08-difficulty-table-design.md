# 난이도표 연동 설계 (2026-10-08)

BMS 난이도표(difficulty table)를 Beetle에 연결한다. [Chart Identity 설계](2026-10-08-chart-identity-design.md)에서 차트의 SHA-256과 MD5가 난이도표의 식별자와 일치한다는 것을 확인했고(Satellite 표 15곡 전부 일치), 이 문서는 그 위에서 표를 내려받고, 내 차트와 맞추고, 곡 선택 화면에 보여주는 방법을 정한다. 구현 전 설계다.

## 목표와 범위

- 하려는 일: 표에 있는 차트가 내 라이브러리의 어느 차트인지 알아내서, 곡마다 표 레벨(`sl3` 같은 칩)을 보여주고, 표를 폴더로 골라 레벨 순으로 볼 수 있게 한다.
- 하지 않는 일: 코스(`course`, 단위 인정), 없는 차트의 목록과 받기 링크(Library 단계), 표 안의 평가/랭킹, 표 편집. 코스는 [chart resolver 계획](2026-10-07-chart-resolver-identity-and-library.md)의 P2 항목이다.

## 확정된 결정 (사용자 선택)

1. **내려받기와 갱신은 `bpm` CLI가 한다.** `bpm`이 표를 받아 가벼운 텍스트 캐시로 저장하고, 앱은 그 파일만 읽는다. 앱은 네트워크와 JSON 의존성을 갖지 않는다.
2. **표는 폴더로, 곡에는 레벨 칩을 붙인다.** 설치된 표마다 곡 선택 화면의 폴더(F1/F3 순환)가 하나씩 생기고, 모든 곡 줄에는 해당하면 `sl3` 같은 칩이 붙는다.
3. **표에는 있지만 내게 없는 차트는 목록에 넣지 않는다.** 폴더 제목에 보유 수(`15 / 2,467`)만 보여준다. 없는 차트 목록과 받기 링크는 Library 단계에서 다룬다.

## 표 형식 (bmstable)

표는 HTML 페이지 하나와 JSON 두 개로 이루어진다.

```text
table.html   <meta name="bmstable" content="header.json">
header.json  { "name": "Satellite", "symbol": "sl", "data_url": "score.json",
               "level_order": [...] (선택), "course": [...] (이 설계는 무시) }
score.json   [ { "md5": "...", "sha256": "...", "level": "3", "title": "...",
                 "artist": "...", "url": "...", "url_diff": "...", ... }, ... ]
```

Satellite의 실제 데이터로 확인한 것: 2,467개 항목 전부에 `md5`와 `sha256`이 있고, `level`은 문자열이다. 다른 표는 `sha256`이 없거나, `level`이 숫자이거나, 필드가 더 있을 수 있어서 읽을 때 다음을 허용한다.

- `md5`, `sha256` 중 하나만 있어도 된다. 둘 다 없는 항목은 건너뛴다.
- `level`은 문자열이든 숫자든 문자열로 받는다.
- 모르는 필드는 무시한다. UTF-8 BOM이 앞에 붙어 있어도 읽는다.
- `data_url`은 `header.json` 주소를 기준으로 한 상대 주소일 수 있다.

## 구조

```text
bpm table add|update|list|remove      네트워크 + JSON. 표를 받아 캐시로 바꾼다
        │  tables/<이름>.tbl
        ▼
beetle-core::table                    캐시 읽기/쓰기, 인덱스, 레벨 정렬 (순수 알고리즘)
        ▼
beetle-app                            시작할 때 읽고 내 곡과 맞춘다. 칩, 폴더, 보유 수
```

- **JSON과 네트워크는 `bpm`에만 있다.** `bms-package-manager`는 이미 `serde_json`과 `ureq`에 의존한다. 앱의 의존성은 늘지 않는다.
- **캐시 읽기와 쓰기는 `beetle-core`에 둔다.** `bpm`이 쓰는 코드와 앱이 읽는 코드가 같아야 하므로 한 곳에 둔다. `bpm`은 이미 `beetle-core`에 의존한다.
- 앱의 위치 관례를 따라 `tables/` 폴더에 둔다 (`songs/`, `replays/`와 같은 층).

### 캐시 파일 형식

`필드=값` 머리말 뒤에 항목 줄이 이어지는 텍스트다. 점수 파일처럼 모르는 머리말 필드는 무시한다.

```text
#BEETLE_TABLE_V1
name=Satellite
symbol=sl
source=https://example.invalid/sl/header.json
fetched=1791500000
levels=0,1,2,3,...            (표가 순서를 줄 때만)
#ENTRIES
<level>\t<md5>\t<sha256>\t<title>\t<artist>\t<url>\t<url_diff>
```

- 필드 안의 탭과 줄바꿈은 기존 곡 목록 캐시와 같은 방식으로 이스케이프한다.
- `md5`나 `sha256`이 없으면 빈 칸이다.
- `fetched`는 마지막으로 받은 시각이다. `source`는 `bpm table update`가 다시 받을 주소다.
- 같은 내용은 같은 바이트가 되도록 항목은 받은 순서를 그대로 유지한다 (표 안의 순서도 의미가 있을 수 있다).

### `bpm table` 명령

| 명령 | 동작 |
|---|---|
| `bpm table add <주소>` | `table.html`이나 `header.json` 주소를 받아 표를 설치한다 |
| `bpm table update [이름]` | 설치된 표를 다시 받는다 (이름이 없으면 전부) |
| `bpm table list` | 설치된 표의 이름, 기호, 항목 수, 받은 시각 |
| `bpm table remove <이름>` | 캐시 파일을 지운다 |

받는 순서: 주소가 HTML이면 `<meta name="bmstable" content="…">`로 `header.json`을 찾고, 아니면 주소를 `header.json`으로 본다. `header.json`의 `data_url`을 따라 데이터를 받는다. 안전 장치:

- `http`와 `https`만 허용하고, 응답 크기에 상한(32MB)과 시간 제한을 둔다. 리다이렉트는 몇 번까지만 따른다.
- 받은 내용은 임시 파일에 쓴 뒤 이름을 바꿔서, 중간에 실패해도 이전 캐시가 남는다.
- 항목이 하나도 읽히지 않으면 기존 캐시를 지우지 않고 오류로 끝낸다.
- 요청에는 식별 가능한 `User-Agent`를 붙이고, 같은 표를 짧은 시간에 반복해서 받지 않도록 `fetched` 이후 일정 시간 안에는 `update`가 확인 질문을 한다 (표 운영자에게 부담을 주지 않기 위해).

## 맞추기

곡 목록이 만들어진 직후 앱이 표마다 인덱스를 만든다.

- 항목의 `sha256`이 곡의 `ChartId`와 같으면 맞는 것이다. `sha256`이 없는 항목은 `md5`로 곡의 `md5` 별칭과 비교한다.
- 한 항목에 `sha256`과 `md5`가 모두 있는데 서로 다른 곡을 가리키면 **`sha256`을 따른다.** MD5는 충돌 저항이 없다.
- 같은 차트가 같은 표에 두 번 나오면 먼저 나온 항목을 쓴다. 여러 표에 나오면 설치 순서대로 모두 기록한다.
- 폴더와 패키지에 같은 차트 파일이 따로 들어 있으면(같은 `ChartId`) 곡 목록에는 항목이 둘이지만 같은 표 레벨을 얻는다.
- 비용은 곡 수와 항목 수에 비례하는 해시 조회뿐이다 (표 10개, 항목 5만 개에 대해서도 눈에 띄지 않는다). 곡 목록이 바뀌면(F5) 다시 만든다.

## 레벨 순서

표마다 레벨 이름이 다르다 (`0`, `12`, `★3`, `sl2`, `?`). 정렬 순서는 다음과 같다.

1. `header.json`에 `level_order`가 있으면 그 순서를 따르고, 목록에 없는 레벨은 맨 뒤에 이름순으로 둔다.
2. 없으면 이름을 자연 정렬한다. 숫자로 시작하는 부분은 숫자로, 나머지는 글자 순으로 비교한다 (`2` < `10` < `10a` < `?`).

## 화면

- **칩**: `{기호}{레벨}`, 예: `sl3`. 곡 목록의 각 줄에 붙이고, 여러 표에 있으면 설치 순서의 첫 표만 붙인다. 상세 패널에는 해당하는 표를 모두(최대 3줄) 이름과 레벨로 보여준다.
- **폴더**: `SongCategory`에 표 폴더를 추가하고, F1/F3 순환에 설치된 표만큼 끼워 넣는다. 폴더 제목은 표 이름과 보유 수(`SATELLITE  15 / 2,467`)다.
- **정렬**: 표 폴더 안에서는 레벨 순서가 먼저이고, 같은 레벨 안에서는 현재 정렬 설정(제목, 클리어 램프 등)을 따른다. 검색은 폴더 안에서 동작한다.
- **빈 표**: 보유한 차트가 하나도 없는 표 폴더도 목록에서 빼지 않는다 (0 / N으로 보인다).
- 클리어 램프와 점수는 이미 `ChartId` 기준이라 칩이 붙은 곡에서 그대로 보인다. 레벨별 클리어 통계 같은 표 전용 화면은 이번 범위가 아니다.

## 구현 단계

1. **core**: `beetle-core::table` 모듈. 캐시 읽기/쓰기, 레벨 정렬, 인덱스(곡 목록과 맞추기), 단위 테스트. 이 단계가 끝나면 앱과 `bpm` 모두가 쓸 수 있다.
2. **bpm**: `bpm table` 명령. HTML 메타 태그 처리, JSON 읽기, 변환, 안전 장치. `bpm serve`가 있으므로 로컬 서버로 받기 전체를 시험하는 테스트를 만들 수 있다.
3. **app**: 시작할 때 `tables/`를 읽고 곡과 맞춘다. 칩, 폴더, 보유 수, 상세 패널.

각 단계는 별도 커밋으로 하고, 단계 2 이후에 Satellite 표로 끝에서 끝까지 확인한다.

## 위험과 미정

- **표마다 JSON이 조금씩 다르다.** 위의 허용 규칙으로 흡수하지만, 실제 표 몇 개로 확인해야 한다 (Satellite 외에 Stella, 발광 등). 단계 2에서 최소 두 개 이상 받아 본다.
- **표 서버가 바뀌거나 사라질 수 있다.** 캐시가 남아 있으면 앱은 계속 동작하고, `bpm table update`가 실패해도 이전 캐시를 건드리지 않는다.
- **큰 표**: 항목이 수만 개여도 캐시 읽기는 한 번의 순차 읽기다. 곡 선택 화면이 열릴 때가 아니라 시작할 때 읽는다. 시작 시간에 영향이 있으면 측정해서 나중에 인덱스를 별도 파일로 두는 것을 검토한다.
- **한글·일본어 제목**: 칩은 기호와 레벨만 쓰므로 영향이 없고, 표 이름은 내장 폰트에 없는 글자가 있으면 기존 글자 대체 경로를 탄다.
- **표가 가리키는 파일이 내 것과 한 글자라도 다르면 맞지 않는다.** 인코딩이나 줄바꿈만 다른 복사본은 표에서 "없는 차트"로 보인다. 이는 다른 플레이어와 같은 동작이다. 같은 곡의 다른 판을 묶는 일은 Library 단계의 `ContentKey`가 맡는다.
- **`url_diff`**: 차분(差分) 받기 주소다. 캐시에는 저장하지만 이번에는 쓰지 않는다. 없는 차트를 받는 흐름(패키지 diff 시스템과의 연결)에서 쓸 후보다.
