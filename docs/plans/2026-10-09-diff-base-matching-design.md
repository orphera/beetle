# 차분의 원본(본체) 후보 추정 설계 (2026-10-09, 리뷰 반영)

난이도표 항목의 차분을 받기 전 또는 받은 뒤에, 사용자가 이미 가진 곡 폴더 중 어느 것이 그 차분의 원본인지 **후보로** 좁혀 주는 기능의 설계다. 구현 전 설계다.

## 1. 문제

- 차분 譜面은 원본 譜面을 고친 파일이라 바이트가 다르다. 원본과 해시가 맞을 수 없다.
- 난이도표 항목에도 원본을 가리키는 필드가 없다. 항목에 있는 것은 차분 譜面의 `md5`/`sha256`, 제목, 아티스트, 레벨, `url`(본체), `url_diff`(차분)뿐이다.
- 따라서 원본 특정은 **해시로 할 수 없고**, 리소스 이름과 메타데이터로 추정한다. 결과는 확정이 아니라 후보다.
- 이 설계가 다루는 것은 **이 차분이 사용자의 어느 곡과 같은 곡인지**(묶기 판단)다.
- 설치 위치 결정은 범위 밖이다. 기존 `get_from_body`는 사용자가 준 본체 아카이브를 임시 폴더에 풀고 패키지로 가져오는 흐름이라, 기존 라이브러리 폴더에 합치지 않는다.

## 2. 확인한 사실

코드와 자료에서 확인한 것만 적는다.

- 소유 판정은 해시로 한다. `ChartId`는 SHA-256이고 MD5는 별칭(alias)으로 함께 저장한다 ([crates/beetle-core/src/identity.rs](../../crates/beetle-core/src/identity.rs)). 이 설계는 소유 판정을 바꾸지 않는다.
- 키음 선언은 `declared_key_sounds`가 `#WAVxx`를 읽어 얻는다. 파일 찾기는 `folder_sound_candidates`가 확장자 대체(`wav`, `ogg`, `flac`, `mp3`)까지 한다 ([crates/beetle-core/src/key_sounds.rs](../../crates/beetle-core/src/key_sounds.rs)). 이 함수는 한 이름의 후보 경로만 돌려준다. 폴더 내용을 나열하지 않는다.
- 곡 묶기 규칙은 [crates/bms-package-manager/src/songs.rs](../../crates/bms-package-manager/src/songs.rs)에 있다.
  - Rule 1: 같은 위치(place)의 譜面은 제목이 충분히 같을 때 제목을 기준으로 묶고, 나머지는 키음이 겹칠 때 붙는다.
  - Rule 2: 다른 위치의 譜面은 제목·아티스트가 같고 `sounds_match`가 맞을 때 묶는다. 제목·아티스트만 같으면 후보로만 보여 준다.
  - `sounds_match`는 Jaccard 0.5 이상과 교집합 8 이상, 또는 작은 쪽 포함률 0.9 이상과 16 이상이다.
  - `mostly_serial`: 일련번호형 이름(`01`, `001`, `0a`)이 과반이면 키음으로 판정하지 않는다.
  - `folder_sounds_match`: 같은 폴더 안의 이상치는 공통 4개 이상이고 자기 키음의 80% 이상이면 묶는다.
  - `title_base`는 전각·공백을 정리하고 **대소문자를 유지**한다. 묶기 비교에서는 소문자로 바꿔 쓴다.
  - `artist_key`는 소문자로 바꾼 뒤 ` obj`, `(obj`, `/obj`, ` / ` 중 처음 나오는 곳에서 **잘라낸다**. `notes` 같은 접두어는 처리하지 않는다.
- 난이도표 조회는 해시만 쓴다 (`table_ops.rs`의 `missing_rows`). 제목은 쓰지 않는다.
- `bpm song link`는 인덱스에 있는 chart를 2개 이상 받아 한 곡으로 묶는다. 폴더 단위 명령이 아니다.
- 외부 참고 구현은 BeMusicSeeker 비공식 포크(Neeted/bemusicseeker-unofficial-fork)다. 명세 `devdocs/spec/library/install-estimation.md`를 읽었다. 저장소 라이선스는 MIT다. 이 설계는 아이디어만 참고하고, 임계값과 정규화는 beetle에서 새로 정한다. 코드를 옮기면 MIT 저작권 표시를 함께 남긴다.

## 3. 설계

### 3.1 두 단계

**단계 A: 받기 전 (제목·아티스트만)**
- 난이도표 항목의 제목·아티스트를 로컬 곡과 비교한다. 정규화는 `title_base`와 `artist_key`에 소문자화를 더해 쓴다.
- 결과는 후보 목록이다. 키음 근거가 없으므로 메타데이터 등급은 최대 "약함"이고, 자동 연결하지 않는다.

**단계 B: 차분을 받은 뒤 (키음 + 메타데이터)**
- 차분 파일이 로컬(또는 임시 폴더)에 있고 인덱스에 등록되어 있을 때만 동작한다.

### 3.2 키음 집합의 정의

모든 키는 `songs.rs`의 키음 정규화 규칙(소문자화, 확장자 제거, 상대 경로 유지)으로 만든다. 구현 때 함수 이름을 확인한다.

- **`F(place)`**: 같은 place에 있는 intact 譜面들의 키 집합 합집합. place는 `songs.rs`의 정의를 따른다. 재귀 여부는 구현 전에 확인하되, 기본값은 **직속 파일만**(비재귀)이다. 비재귀면 조상 억제 규칙은 필요 없다.
- **`S_d`**: 차분 譜面이 선언한 키음 집합에서, 차분 팩이 함께 가져오는 파일(동봉 키음)을 뺀 것이다. 즉 원본에서 와야 하는 키음만 남긴다.
- 인덱스에 있는 `key_stems`와 `missing_keys`를 쓰면 파일을 다시 읽을 필요가 없다. 대상은 사실상 `missing_rows`의 `body_needed` 행이다.

### 3.3 점수

후보 place마다 다음을 계산한다. 교집합 `I = |S_d ∩ F|`.

- 충족률 `c = I / |S_d|`: 원본에서 와야 하는 키음 중 후보가 가진 비율.
- 정밀도 `p = I / |F|`: 후보가 가진 키음 중 차분과 관련 있는 비율. 여러 곡이 섞인 폴더는 `p`가 낮아진다.
- Jaccard `j = I / |S_d ∪ F|`.

### 3.4 후보 조건과 판정

1. `|S_d| = 0`이면 단계 B를 쓸 수 없다. 단계 A 결과만 보여 준다.
2. `I < 2`인 후보는 버린다.
3. `S_d`에서 일련번호형 이름이 과반이면 키음 판정 전체를 하지 않고 단계 A로 내린다.
   `F`(place)에서 일련번호형 이름이 과반이면 그 place만 키 후보에서 뺀다. 빠진 place 중 제목·아티스트가 맞는 곳은 약함 등급으로 따로 보여 준다.
4. `c ≥ 0.8`인 후보만 남긴다. 기준 0.8은 초안이다.
5. **높은 확신도**는 다음을 모두 만족할 때만 준다.
   - `I ≥ 4` (`folder_sounds_match`와 같은 하한)
   - `p ≥ 0.5` (초안)
   - 메타데이터 등급이 "없음"이 아님
   - 1위 후보가 **모든 후보**보다 `c`와 `p` 모두에서 같거나 높고, 2위보다는 둘 중 하나가 더 높음 (동점이면 높은 확신도를 주지 않는다)
6. 파싱 실패로 `declared_key_sounds`가 `None`이면 단계 A로 내린다.

### 3.5 순위

1. `c` 높은 순.
2. `p` 높은 순.
3. 메타데이터 등급 (강함 > 약함 > 없음).
4. `j` 높은 순.
5. 마지막은 place id 사전순으로 고정해, 입력 순서와 무관하게 결과가 같게 한다.

- 확신도는 **1위에 대해서만** 판정한다. 1위가 **모든 후보**보다 `c`와 `p`에서 같거나 높고, 2위보다는 둘 중 하나가 더 높을 때만 확신도 높음을 준다. 정렬 앞쪽에 "확신도 조건 만족 여부"를 두지 않는다. 그렇게 하면 확신도 있는 후보가 더 잘 맞는 후보보다 앞서는 모순이 생긴다(리뷰 지적, 구현 때 이렇게 정함).

### 3.6 메타데이터 등급

정규화된 제목(`title_base` 후 소문자)과 아티스트(`artist_key`)를 비교한다. 제목 유사도는 바이그램 Dice 계수다.

| 등급 | 조건 |
|---|---|
| 강함 | 아티스트가 정확히 같고, 제목이 정확히 같거나 제목 유사도가 0.88 이상이다. |
| 약함 | 제목이 정확히 같다. 또는 아티스트만 정확히 같다. 또는 제목 유사도가 0.72 이상이다(아티스트가 달라도 포함). |
| 없음 | 나머지 |

- 제목만 정확히 같은 경우는 흔한 제목 때문에 강함으로 치지 않는다. 포크는 이 경우를 강함으로 보지만, beetle에서는 약함으로 둔다.
- 단계 A(제목·아티스트만)에서는 등급을 **약함까지만** 준다. 강함은 키음 근거가 있을 때만 쓴다.
- 임계값 0.88과 0.72는 포크 코드의 값을 참고한 초안이다. beetle 자료로 검증해 조정한다.

### 3.7 결과와 적용

| 상황 | 표시 | 자동 적용 |
|---|---|---|
| 높은 확신도 후보 1개 | 확신도 높음 + 후보 1개 | 하지 않는다. 사용자가 확인하면 연결한다. |
| 높은 확신도 없음, 후보 있음 | 상위 3개와 `c`, `p`, 등급 | 하지 않는다 |
| 키음 검사를 했으나 통과한 곳 없음 | "맞는 원본 없음". 다만 일련번호형 키음이라 키로 못 본 폴더 중 제목·아티스트가 맞는 곳은 약함 등급으로 함께 보여 준다 | 없음 |
| 단계 A만 가능 | 제목·아티스트 후보 (등급 최대 약함) | 없음 |

- **자동 적용은 하지 않는다.** 되돌리기 명령(`bpm song unlink`)은 있지만, 잘못 묶이면 사용자가 원인을 찾기 어렵다.
- **연결이 필요한 경우를 좁힌다.** 차분 chart와 후보 place의 chart가 이미 Rule 1 또는 Rule 2로 한 곡이 되어 있으면 연결할 필요가 없다. 연결은 그 규칙이 묶지 못한 경우에만 제안한다. 대표 chart id는 후보 place에서 `c`가 가장 높은 譜面을 쓴다.
- "후보 없음"은 "원본이 없다"는 뜻이 아니다. 키음이 빠졌거나 파일 이름이 다를 수 있다.

## 4. 구현 단계

**1단계: 순수 함수 추정기.**
- 위치: `crates/bms-package-manager/src/` 안의 새 모듈(가칭 `base_match.rs`).
- 입력은 `S_d`, place별 `F`, 메타데이터다. 파일 시스템 접근은 호출자가 맡는다. `key_sounds.rs`와 같은 방식이다.
- 새 의존성은 추가하지 않는다 (AGENTS.md §3). 바이그램 Dice는 표준 라이브러리로 구현한다.
- 역색인(키 → place 목록)은 1단계에서 **만들지 않았다.** 지금은 place를 전부 순회한다. 교집합을 먼저 구하고 무거운 검사는 살아남은 place에만 하도록 순서를 맞췄다. 역색인은 2단계에서 실제 라이브러리 크기로 측정한 뒤 필요하면 추가한다.

**2단계: 표시 명령.**
- `bpm table base <표> <번호>`: 항목의 후보를 출력한다. 단계 A는 받기 전에도 동작한다.
- 단계 B는 차분 파일이 로컬에 있고 인덱스에 등록되어 있을 때만 동작한다.
- 구현 메모 (2단계):
  - 차분 사본이 여러 개면 그 사본이 있는 place를 **모두** 후보에서 뺀다. 키음은 intact 사본을 우선한다.
  - `S_d`의 동봉 키음은 근사한다. 인덱스에는 "어느 키가 실제로 있는지"가 없어서, 차분 사본이 있는 place의 intact 키 중 차분이 선언한 것을 동봉으로 본다. 차분이 불완전한 사본만 있으면 동봉을 빼지 못해 `c`가 낮아질 수 있다. 거짓 음성 쪽으로만 틀린다.
  - 차분이 이미 키음을 모두 갖춘 곳에 있으면 원본은 키음 판정에 필요 없다. 이때는 안내 문구를 내고 메타데이터 후보만 보여 준다.
  - 연결 제안은 두 chart가 이미 같은 곡(`songs::build`)이면 내지 않는다. 대표 chart는 후보 place에서 `required`와 키음이 가장 많이 겹치는 intact 사본이며, 제목을 함께 보여 준다.

**3단계: 연결.**
- 사용자가 확인한 경우에만 기존 `bpm song link`로 연결한다. 새 저장 형식은 만들지 않는다.

## 5. 검증 계획

- **단위 테스트**
  - 충족률·정밀도·Jaccard 계산.
  - `I < 2` 제외, `|S_d| = 0` 처리, 파싱 실패 처리.
  - 일련번호형 이름 제외.
  - 동봉 키음이 분모에서 빠지는지.
  - 동점일 때 높은 확신도를 주지 않는지.
  - 경로 키: `sub/kick`과 `kick`을 다른 키로 취급한다. 같은 키로 보지 않는 것이 기본이다.
  - 입력 순서를 섞어도 결과가 같은지(결정론).
- **음성 세트**: 원본을 가지지 않은 차분을 여러 개 넣었을 때 높은 확신도가 나오면 안 된다.
- **양성 세트**: 사람이 정답을 붙인 원본-차분 쌍 30개 이상으로 고신뢰 오탐을 센다. 목표는 높은 확신도 오탐 0건이다.
- **성능**: 큰 라이브러리에서 역색인으로 후보를 찾는 시간을 측정한다. 전체 순회로 돌아가지 않는지 확인한다.
- **기준 조정**: 0.8, 4, 0.5, 0.88, 0.72는 검증 결과로 조정하고, 바꾼 이유를 이 문서에 남긴다.

## 6. 범위 밖

- 차분이 어느 원본에서 파생됐는지 증명하지 않는다. 확정 판정도 하지 않는다.
- 해시로 원본을 찾지 않는다. 해시는 소유 판정과 중복 판정에만 쓴다.
- 자동 연결과 자동 설치 위치 선택은 하지 않는다.
- 설치 위치 결정은 이 설계에서 다루지 않는다.
- 난이도표 항목에 키음 목록을 추가하지 않는다. 표 형식을 바꾸지 않는다.
- IDF처럼 여러 곡에 흔한 키음의 가중치 낮추기는 나중 과제로 둔다. 1차 구현에서는 정밀도로 대신한다.

## 7. 결정이 필요한 것

1. 단계 A를 먼저 만들지, 단계 B까지 한 번에 만들지. 추천은 A 먼저다. 받기 전에도 쓸 수 있고 위험이 낮다.
2. 기준값(0.8, 4, 0.5)을 초안으로 시작할지, 검증 자료로 먼저 정할지. 추천은 초안으로 시작하고 검증 후 조정이다.
3. 포크의 퍼지 제목 규칙(0.88)을 그대로 쓸지. 추천은 그대로 쓰고 검증 때 조정이다.
5. (해결함, 구현 완료) 확신도는 1위가 **모든 후보**보다 `c`, `p` 모두 같거나 높을 때만 준다. 3위가 `p`에서 더 높으면 확신도를 주지 않는다.
6. **같은 원본의 사본이 둘 이상이면** (폴더 등록과 설치 패키지가 함께 있거나 등록 폴더가 겹치면) 키 집합이 같은 place가 여럿 생겨 항상 동점이 된다. 지금은 확신도를 주지 않는다. 키 집합과 제목·아티스트가 모두 같은 place들은 "같은 곡"으로 보고 확신도를 주는 규칙을 검토할 만하다. 구현에서는 아직 바꾸지 않았다.

## 8. 미확인

- 확인함: `songs.rs`의 place는 경로에서 마지막 `/` 앞 부분(직속 디렉터리)이다. 비재귀이고, 패키지도 디렉터리 단위로 나눈다. 구현은 이 정의를 따른다.
- 키음 정규화 함수의 정확한 이름과 동작은 구현 때 확인한다. 이 문서는 `key_stems`/`normalize_stem`이라는 이름을 기준으로 한다.
- 실제 난이도표 항목 중 키음 선언이 없는 차분의 비율은 아직 세지 않았다.
- `declared_key_sounds`는 BGA 이미지나 동영상 참조를 포함하지 않는다. 키음만으로 충분한지는 검증이 필요하다.
