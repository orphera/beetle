# 게임 기획 기준 및 일관성 점검 (2026-10-31)

## 목적과 읽는 법

화면·모드·옵션·용어·동작 규칙을 한곳에서 빠르게 파악하기 위한 교차 영역 기준이다. 세부 규칙은 연결된 설계서와 ADR을 따르며, 이 문서는 그 내용을 중복해 대체하지 않는다.

- **확정**: ADR, 아키텍처 불변식, 구현과 테스트로 확인된 동작.
- **기록**: 과거 캡처·구현 과정을 남긴 문서. 당시 상태의 기록이지 현재 구현 지시가 아니다.
- **미정**: 아래 점검 목록 또는 백로그에서 결정을 기다리는 내용. 확정 사항처럼 전제하지 않는다.

## 현재 제품 흐름

- 시작 시 서재를 읽은 뒤 타이틀 메뉴를 거쳐 선곡으로 간다. 선곡에서 곡·채보·폴더·난이도표와 그 표의 코스, 디스크에서 읽은 곡·코스를 고른다. 선곡 외 화면은 로딩, 플레이, 결과, 키 설정, 설정이다. 현재 `SongSelect`는 프리 플레이·디스크·코스에 공통으로 쓰이며, 각각을 먼저 고르는 별도 최상위 모드는 아직 없다.
- 코스는 여러 채보를 연속 플레이하고 마지막에 코스 결과를 보여준다. 난이도표 코스와 CS 디스크 단위인정은 같은 코스 실행 흐름을 사용하되, 출처와 제약은 구분한다. 단위인정은 코스와 다른 구현 경로가 아니다.
- 구현된 BMS 키 모드는 **4K, 5K, 6K, 7K, 8K, 9K, 10K, 14K**다. 표기에서 `K`가 스크래치를 포함하는지는 별도 용어 결정이 남아 있다. 모드별 실제 레인과 키 기본값은 [멀티키 모드 사양](../specs/multi_key_mode_support.md) 및 해당 구현을 기준으로 한다.
- 수동 플레이 입력은 도착 순간의 오디오 시각으로 판정한다. 판정과 노트 위치는 오디오 클럭을 기준으로 하며 렌더 프레임 시각으로 진행하지 않는다. 디코딩과 무거운 파일 작업은 백그라운드에서 하고, 재생 중에는 사전 디코딩된 PCM을 쓴다.

## 옵션과 용어 기준

### 옵션의 경계

- **플레이 옵션**: 노트 속도(그린 넘버), 속도 기준 BPM, 레인 커버, 모디파이어, 게이지, LN 모드.
- **세션 옵션**: 자동 플레이, 시작 마디.
- **설정**: 시스템·화면·소리·판정·레이아웃·입력 그룹. 현재 설정 표는 [`options_table.rs`](../../crates/beetle-app/src/options_table.rs)의 그룹·행 정의가 기준이다. 코스 제약이 걸린 옵션은 잠금 값이 우선한다.

### 화면에 쓰는 말

| 주제 | 현재 기준 | 남은 점 |
|---|---|---|
| 언어 | Beetle 앱은 한국어·영어·일본어를 제공하고 설정에서 바꾼다. BMS 관용어와 판정명·램프명·게이지/모디파이어 이름·모드명은 영어를 유지한다. | [`strings.rs`](../../crates/beetle-render/src/strings.rs)의 모듈 설명은 한국어만 제공한다고 적혀 있어 실제 코드와 맞지 않는다. 점검 목록 C5. `bpm-gui`는 별도 앱이며 한국어만 제공한다. |
| 속도 | 설정과 설명은 **노트 속도**를 우선 표기하고, 필요하면 그린 넘버라는 별칭을 설명에 쓴다. 값은 ms다. | 별도 미정 없음. |
| 키 모드 | 현재 모드 라벨은 `4K`부터 `14K`까지 모드별 키 수를 쓴다. | `7+1K`, `5+1K`처럼 스크래치를 분리해 쓸지 B8에서 결정한다. 10K/14K 표기 규칙도 함께 확정한다. |
| 롱노트 | 옵션 `AUTO`는 차트의 `#LNMODE`를 따르고, 선언이 없으면 LN을 쓴다. `#LNMODE 3`(HCN)은 현재 CN 규칙으로 재생한다. 플레이어가 고른 LN/CN 규칙은 차트 규칙보다 우선한다. | [롱노트 규칙 설계](2026-10-08-long-note-rules-design.md)의 이후 과제·범위 밖 항목을 구현 완료로 오해하지 않는다. |
| 난이도 | 차트의 `#DIFFICULTY` 이름을 표시하고, 없을 때만 레벨 구간 표기를 쓴다. 숫자만으로 난이도명을 추측하지 않는다. | 별도 미정 없음. |
| 코스/단위 | UI에서는 코스와 단위인정이 같은 연속 플레이 기능의 일반형·제약형이다. | 사용자가 모드를 먼저 고르게 할 때 둘을 나눌지 B9에서 결정한다. |

## 후속 순서

1. C1–C2 문서 상태를 최신 구현에 맞춘다. 이 단계는 렌더·모드 구현 변경이 아니라 오래된 지시의 정리다.
2. B8과 B9에서 각각 표기 규칙과 최상위 모드 흐름을 결정한다.
3. 저장 형식은 플레이 기록·통계의 질의 요구를 먼저 확정한 뒤 B14에서 조사한다. 이 문서에서는 DB 선택이나 파일 형식을 결정하지 않는다.
4. B6 기어 리디자인과 그 위에 표시될 B5/B7은 B8/B9의 용어·진입 흐름을 반영한 뒤 다룬다.
