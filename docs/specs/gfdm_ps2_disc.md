# PS2 GuitarFreaks & DrumMania 디스크 형식

`crates/cs-disc`의 `gfdm.rs`가 읽는 PS2 GuitarFreaks & DrumMania Masterpiece Silver(`SLPM_664.84`) 디스크의 데이터 형식이다. 디스크 한 장을 직접 읽어 알아낸 것이다(2026-11-10). IIDX는 [iidx_ps2_disc.md](iidx_ps2_disc.md), pop'n은 [popn_ps2_disc.md](popn_ps2_disc.md).

IIDX·pop'n 디스크와 달리 데이터 파일은 **암호화도 압축도 없다**(텍스처 안쪽만 LZSS). 색인 파일 하나로 모든 파일을 꺼낼 수 있고, 파일은 경로의 CRC-32로 찾는다.

## 1. 디스크와 파일

| 경로 | 내용 |
|---|---|
| `SLPM_664.84` | 실행 파일 (2.3MB) |
| `MODULES/*.IRX` | IOP 모듈 |
| `DUMMY.BIN` | 1GB 채움 파일 |
| `DATA/PACK/PACKINFO.BIN` | 색인 (33456바이트) |
| `DATA/PACK/Dnnn/PACKnnnn.PAK` | 데이터 118개. `D000`~`D003`에 30개씩 들어 있고 마지막은 28개. 합계 약 2.27GB |

PAK 번호 `n`은 `D{n/30:03}/PACK{n:04}.PAK`에 있다. PAK에는 따로 머리가 없고, 파일이 이어 붙어 있다.

## 2. `PACKINFO.BIN`

| 위치 | 내용 |
|---|---|
| 0x00 | `0x20041207` (날짜로 보임) |
| 0x04 | `16` |
| 0x08 | 항목 영역 끝 (`0x7b50`) |
| 0x0c | 모름 (`7734234`) |
| 0x10 | 파일 항목 32바이트 × 986 |
| 0x7b50 | 16바이트 × 118. PAK마다 하나이고 PAK의 MD5로 보인다(확인 안 함) |

파일 항목:

| 위치 | 내용 |
|---|---|
| 0x00 | 파일 바이트의 MD5 (986개 모두 일치 확인) |
| 0x10 | `u32` 키: 게임이 여는 경로의 **CRC-32**(zlib와 같은 IEEE). 예: `/data/product/music/m0404/d0404.sq2` → `0xd1f8d571`. 항목은 이 값의 오름차순 |
| 0x14 | `u32`: 위 16비트는 PAK 번호, 아래 16비트는 모름 |
| 0x18 | `u32` PAK 안 오프셋 |
| 0x1c | `u32` 크기 |

내용이 같은 파일은 MD5도 같다. 60바이트짜리 `MDL2` 같은 것들이 그렇다.

## 3. 곡 파일 (PAK 0~73번, 74곡)

곡 하나가 PAK 하나지만, PAK 순서는 곡 번호 순서와 조금 다르다(예: 412번 곡이 52번 PAK). 그러니 PAK 번호로 곡을 찾지 않는다. 게임처럼 곡 번호로 경로를 만들고, 그 경로의 CRC-32로 색인에서 찾는다(`gfdm::song_path`). 경로는 실행 파일의 형식 문자열에 있다.

| 경로 (`m{id:04}` 아래) | 머리 | 크기 | 내용 |
|---|---|---|---|
| `d{id}.sq2`, `g{id}.sq2` | `SEQP` | 29–144KB | DM, GF 채보 (4절) |
| `spu{id}d.va2`, `spu{id}g.va2` | `03 00 00 00`, 0x18에 `SBlk` | 98KB–4.5MB | DM·GF 키음 뱅크 (4.1절). PS-ADPCM |
| `m{id}.pss` | `00 00 01 BA` | 18–58MB | MPEG 프로그램 스트림. 영상은 `0xE0`, 음악은 private stream 1(`0xBD`)의 ATRAC3 스트림 3~5개 (4.2절) |
| `fre{id}.bin` | (없음) | 12–14 | DM 레인마다 기본 노트 `u16` (4.1절). 예: `100, 26, 24, 29, 31, 35, 0` |
| `i{id}gf.at3`, `i{id}dm.at3` | `A2 …` | 약 180KB | 미리 듣기 소리. 컨테이너 없는 ATRAC3 프레임(4.2절), 약 11초. PAK 75(GF)와 74(DM)에 있다 |

모든 경로는 `/data/product/music/m{id:04}/`로 시작하고, `{id}`는 네 자리다. 74곡 모두 채보·영상·키음 다섯 파일이 이 방식으로 찾아진다.

## 3.1 곡 표 `music_info.bin`

`/data/product/music/music_info.bin`(PAK 77). 곡마다 0x5c바이트 레코드가 있고 74개다. 순서는 곡 번호 순이다(실행 파일 0x193c70에도 같은 번호 목록 74개가 있다).

| 위치 | 내용 |
|---|---|
| 0x00 | `u32` 곡 번호 (404–1040). 수백 자리는 원래 수록된 버전으로 보인다 |
| 0x06 | `u16` 표시 BPM. 몇 곡은 채보 템포의 절반(404번: 76, 채보는 152) |
| 0x09 | GF 레벨 3바이트 (BASIC, ADVANCED, EXTREME으로 추정. 예: MODEL DD6 `57, 77, 95`) |
| 0x12 | `u16` 곡 번호 한 번 더 |
| 0x2c | `u32` 곡 길이 (1/300초). 채보 끝 시각과 거의 같다 |
| 0x31 | DM 레벨 3바이트 |
| 0x4c | 이름 16바이트, ASCII, NUL로 끝남. 15자에서 잘린다(`FIRE IN THE DAR`). 일본어 제목은 로마자로 적는다(`MUNAGOTO NO UMI`) |

같은 폴더의 `jp_title.bin`은 글자가 아니다. (곡 번호 `u16`, 번호 `u16`) 짝 23개이고, 일본어 제목이 있는 곡의 목록으로 보인다. `course_info.bin`, `net_id.bin`은 아직 안 봤다.

## 3.2 곡 제목: 배너 그림

온전한 곡 제목(일본어, 아티스트 포함)은 글자로는 디스크에 없다. 200×80 배너 그림 `IMG_CO{id:04}`로만 있다. 배너는 PAK 76의 `TEXP` 파일들(6절)에 텍스처 묶음으로 들어 있다. 한 파일에 256×256 텍스처가 여러 장 있고, 이름 있는 사각형(`TCER`)이 배너 하나를 가리킨다. 74곡의 배너가 모두 있다. 그림 속 글자는 예를 들어 `空宮の海 / 音々`, `本日ハ晴天ナリ`, `Moonlight Walkin' / 入尾信充 with Van Yan`이다.

같은 이름의 배너가 여러 파일에 들어 있기도 하다. 지금은 처음 찾은 것을 쓴다. 어느 파일이 어느 화면용인지는 아직 모른다. 파일 이름(경로)을 몰라서 CRC-32로 바로 찾을 수 없으므로, `Disc::texture_files`로 텍스처 파일을 모두 훑어 이름을 모은다. 39MB를 읽으므로 앱에서는 결과를 저장해 두고 써야 한다.

`beetle-render`의 MPEG 디코더(`mpeg-video`)는 프로그램 스트림을 읽으므로 영상은 그대로 쓸 수 있을 것이다.

## 4. `SEQP` 채보

머리 0x30바이트:

| 위치 | 내용 |
|---|---|
| 0x00 | `SEQP`, `00 00 02 00`, `00 00 01 00` |
| 0x0c | 파일 크기 |
| 0x14 | `0x194` (모름) |
| 0x18 | 트랙 수 |
| 0x20 | 첫 트랙의 바이트 길이 |

이어서 `SEQT` 트랙이 나온다. 각 트랙은 0x20바이트 머리, 이벤트 16바이트 × 개수, 그리고 마지막 트랙을 뺀 나머지 트랙에만 붙는 16바이트(모름, 처음 4바이트는 시각 같은 값)로 되어 있다.

| 트랙 머리 위치 | 내용 |
|---|---|
| 0x00 | `SEQT`, `00 00 02 00`, `00 00 01 00`, `0x20` |
| 0x10 | 이벤트 수 (끝 이벤트 포함) |
| 0x14 | 게임: 0 DM, 1 GF |
| 0x15 | 1이면 메타 트랙 (템포·마디) |
| 0x16 | DM: 난이도 1 BASIC, 2 ADVANCED, 3 EXTREME. GF: 1~3 |
| 0x17 | DM: 0. GF: 1 기타, 2 베이스, 일부 곡은 3 |

첫 트랙은 메타 트랙이다. DM 파일은 메타 + 난이도 3개다. GF 파일은 메타 + (0x16, 0x17) 조합 4~8개다. GF에서 0x16이 난이도인지는 아직 확실하지 않다. 0x16만 다르고 노트 수가 같은 트랙도 있다(0번 곡 `GF2.1`·`GF3.1`, 3번 곡 `GF1.1`·`GF2.1`·`GF3.1`).

이벤트 16바이트:

| 위치 | 내용 |
|---|---|
| 0x00 | `u32` 시각. **1/300초 단위의 절대 시간**이다. 152BPM 곡에서 한 마디가 474틱이다 |
| 0x04 | 값: DM 노트는 레인 0–5, GF 노트는 프렛 비트(1 R, 2 G, 4 B)이고 `0x20`은 와일링이나 오픈으로 추정 |
| 0x05 | 종류 (아래) |
| 0x08 | `u32`: 노트는 소리 키(아래 16비트, 4.1절), 템포는 박당 µs |
| 0x0c | `u32`: 노트는 볼륨(`0x7f`), 박자는 `0x204`(4/4) |

| 종류 | 뜻 |
|---|---|
| 0x00 | 노트 |
| 0x10 | 템포 |
| 0x20 | 박자 |
| 0x30, 0x40 | 메타 트랙 시작과 끝에 하나씩 (모름) |
| 0x50 | 마디선 |
| 0x60 | 박선 |
| 0x70, 0x80 | 플레이 트랙의 시작과 끝 표시 |
| 0xe0, 0xf0 | 트랙 시작과 끝 |

시각이 절대 시간이므로 BMS로 바꿀 때 템포를 따라 위치를 다시 계산할 필요가 없다. 템포 이벤트는 마디를 나누는 데만 쓰면 된다.

## 4.1 키음

노트(종류 0)와 자동 소리(종류 1)의 `u32` 0x08 아래 16비트가 소리 키다. 키 → 소리 표는 곡 파일이 아니라 **실행 파일 `SLPM_664.84`에 있다**(`gfdm::Kits`). 실행 파일 위치는 ELF 첫 프로그램 머리로 바꾼다(파일 위치 = 주소 − 0x100000 + 0x80).

- 0x193c70: 곡 번호 74개(`u32`, 오름차순). 아래 표들은 모두 이 순서다.
- 0x1940b0: DM 키트 포인터 74개. 키트는 (`u16` 키, `u16` 소리 번호) 짝이 이어지고 키 `0xff00`에서 끝난다. DM 키는 GM 드럼 번호와 비슷하다(36 킥, 40 스네어, 49 크래시, 100~106 하이햇). DM 뱅크는 하나다.
- 0x1941e0: GF 키트 포인터 74개. GF 키트는 0xa0바이트 조각이 이어진 것이다. 조각 하나는 같은 짝 목록으로, 위 바이트 `hi`가 같은 키(`hi << 8 | 음`)만 담는다. 첫 키가 `0xffff`인 조각에서 끝난다.
- 주소 0x28bde0: GF 뱅크 표 포인터 74개. 표는 `hi`마다 8바이트(`u32` 샘플 파일 안 위치, 크기)다. **11곡은 뱅크가 `hi` 순서로 놓여 있지 않으므로**(539번은 `hi` 0xa0~0xe2 뱅크가 맨 앞) 이 표로 찾아야 한다. 게임 코드(주소 0x16a370 부근)는 `hi`로 이 표를 찾아 뱅크를 SPU에 올리고, 0x293ffc의 "올린 `hi`" 표와 맞는 뱅크로 소리를 낸다.
- 키가 DM 키트에 없으면(6곡의 0~14 같은 작은 값, 860노트) 그 레인의 기본 노트 `fre[값]`을 쓴다. 모든 DM 노트의 64%는 키가 원래 레인 기본 노트와 같다. 이 규칙을 넣으면 디스크의 모든 노트가 소리를 찾는다.

샘플 파일(`va2`)은 뱅크가 이어진 것이다. 뱅크마다 24바이트 머리 `(3, 2, 0x18, SBlk 크기, 소리 데이터 위치, 크기)`(위치는 뱅크 기준), `SBlk`, 소리 데이터가 오고, 다음 뱅크는 다음 16바이트 경계(채움 0x77)에서 시작한다. DM 파일은 뱅크 1개, GF 파일은 7~44개다.

`SBlk`(Sony SCREAM 뱅크): 0x16 `u16` 소리 수, 0x1c 소리 표(12바이트, 0x08 `u32` 프로그램 위치), 0x20 프로그램 표(8바이트, 첫 `u16`이 톤 위치), 0x34 톤 표(24바이트)다. 위치는 모두 `SBlk` 기준이다. 톤: 1 볼륨, 2 음 높이, 3 미세 조정(늘 0x42), 4 `u16` 팬(도), 10·12 ADSR(늘 `80ff`, `9fc0`), 0x10 `u32` 소리 데이터 위치. 소리 데이터는 PS-ADPCM(`adpcm::decode`, 키 없음)이고 끝 플래그에서 멈춘다.

음 높이 `0xc2`가 44100Hz이고 한 칸이 반음이다(`0xb6`은 22050Hz). GF 기타 소리는 키의 음(0x24…)과 같은 반음 간격으로 녹음되어 있어서 44100Hz로 들으면 키 음과 맞는다. GF 키의 `u32` 위 16비트는 길이(틱)다.

## 4.2 음악 (ATRAC3)

영상의 private stream 1(`0xBD`) 패킷은 PES 머리 뒤에 `ff 90`, 빅 엔디언 `u16` 스트림 번호가 오고, 나머지가 ATRAC3 데이터다(`gfdm::movie_audio`). 스트림 번호별로 이어 붙이면 384바이트 프레임(채널마다 192바이트, joint stereo 아님), 44100Hz 스테레오가 된다. 미리 듣기 `.at3`도 같은 프레임이 머리 없이 있다.

- 보통 곡은 스트림 1~5가 있다. 3분이 넘는 긴 곡 9곡(528, 531, 622, 726, 727, 821, 823, 926, 1028)은 2, 3, 5만 있다. 1~3은 길이가 같고 4·5는 몇 초 길다.
- 스트림끼리 상관은 0.6~0.7로, 같은 곡의 다른 믹스다. 어느 스트림이 어느 모드(GF 단독, DM 단독, 세션)용인지는 아직 모른다. 차트를 키음으로 그린 소리와 어느 스트림을 비교해도 같은 파형이 없으므로, 스트림에는 연주 파트 키음이 들어 있지 않다.

`atrac3.rs`는 의존성 없는 ATRAC3 디코더다(이 디스크가 쓰는 독립 스테레오만). 참조 디코더(ffmpeg)와 비교해 404번 곡 스트림 5개와 미리 듣기가 모든 샘플에서 ±1 안이다. 역 MDCT는 교과서 식과 부호가 반대다.

## 5. 곡이 아닌 PAK (74~117번)

| PAK | 내용 |
|---|---|
| 74, 75 | 곡별 미리 듣기 `i{id}dm.at3`, `i{id}gf.at3` (ATRAC3) |
| 76, 78, 90 등 | `TEXP`(`PXET`) 텍스처, `MDL2`(`2LDM`) |
| 77 | `music_info.bin`·`jp_title.bin`·`course_info.bin`·`net_id.bin`, 시스템 BGM `system/MT_*.at3`, `se.vas`, `gf_s`, 32KB 표들 |
| 115 | `PS2D`(964바이트) 하나와 `00000100` 파일 하나 |
| 117 | 영상 2개(데모나 오프닝으로 보임) |

경로를 아는 파일은 986개 중 610개다(곡 파일과, 실행 파일에 경로가 그대로 적힌 파일들).

## 6. `TEXP` 텍스처 (`texp.rs`)

Konami의 텍스처 묶음이다. 리틀 엔디언이라 디스크에서는 마법 값이 거꾸로 `PXET`, `PMAN`, `TCER`, `TDXT`, `DLAP`로 보인다.

| 위치 | 내용 |
|---|---|
| 0x14 | 텍스처 수 |
| 0x1c | 첫 텍스처 데이터 위치 |
| 0x20 | `TCER`(사각형 표) 위치. 없으면 0 |
| 0x40 | `PMAN`: 텍스처 이름 표 |

- `PMAN`: 0x10에 개수가 있고, 0x1c부터 12바이트 항목(해시, 번호, 이름 위치)이 이어진다. 이름 위치는 `PMAN` 기준이고 NUL로 끝난다.
- 텍스처: 빅 엔디언 `u32` 풀린 크기와 압축 크기, 그다음 LZSS(IIDX 텍스처와 같은 4KB 링 버퍼, `ps2tex::decode_lzss`)다. **압축 크기가 0이면 `TDXT`가 압축 없이 그대로 있다**(디스크 전체 2065장 중 8장). 다음 텍스처는 4바이트 정렬 위치에서 시작한다.
- 풀린 `TDXT`: 0x10에 `u16` 너비와 높이, 0x14에 픽셀 형식이 있다. `0x12`는 한 바이트 한 픽셀(1845장), `0x11`은 4비트 한 픽셀이고 아래 니블이 먼저다(212장). 0x16은 `0x22`나 `0x11`인데 뜻은 모르고, 그림에는 영향이 없다. 0x40부터 픽셀이 행 순서로 있고 스위즐하지 않는다.
- 픽셀 뒤에 `PALD`(`DLAP`)가 온다. 0x14바이트 머리이고, 0x0c에 블록 크기, 0x10에 `u16` 색 수(16, 43, 196, 256 등)가 있다. 그 뒤에 RGBA 색이 **그냥 순서대로** 있다. GS의 CSM1 순서가 아니다. 이 순서를 바꿔 읽으면 배너가 점무늬로 깨진다. 알파는 0xff까지 쓴다.
- 픽셀과 팔레트를 읽고 나면 남는 바이트가 없다(한 장만 팔레트가 색 수보다 짧다). 아직 뜻을 모르는 것은 `TDXT` 머리의 0x16과 0x18~0x3f, 그리고 `PMAN` 항목의 해시다.
- `TCER`: 0x18에 사각형 데이터 위치(`TCER` 기준), 0x1c에 이름 `PMAN`이 있다. 사각형은 12바이트로, `u32` 텍스처 번호와 `u16` x1, x2, y1, y2(끝은 포함하지 않음)다.

## 7. BMS로 플레이하기

`gfdm_bms::to_bms`가 채보 하나를 BMS로 쓴다. 앱은 `disc:<이미지>::gfdm/<번호>/dm<d>|gf<d>|bass<d>`로 연다(`beetle-app`의 `loader/gfdm.rs`, 선곡 목록은 `scanner.rs`).

- DM은 6K(채널 11,12,13,15,18,19), GF·베이스는 4K(R/G/B → 11,12,14, 네 번째는 열린 피크용으로 비움).
- 마디는 메타 트랙의 마디선(0x50), 템포는 0x10 이벤트(한 박의 µs)로 `#BPMxx`·채널 08을 쓴다. 위치는 마디당 960 격자를 약분한다.
- 음악은 영상의 첫 스트림을 `music.wav`로 0마디에 둔다. 같은 난이도의 다른 파트는 자동 소리로 깐다(DM → GF 기타, GF → DM, 베이스 → DM과 기타).
- 화음에서는 첫 프렛만 소리를 내고 나머지는 `silent.wav`.
- 영상은 그대로 BGA로 튼다.

## 8. 아직 할 일

할 일 번호는 [TASKS.md](../TASKS.md)의 B22~B25. 확인한 것: CLASSIC PARTY 3(404) DM·GF HYPER 오토플레이 캡처, 노트 시각이 디스크와 3ms 안, 키음 빠짐 없음, 581채보·74곡 목록(env `CS_DISC_GFDM` 테스트). 확인 안 한 것: 실제 키 입력, BGA 켠 영상 재생.


- 음악 스트림 1~5가 각각 어느 모드용인지 (들어 보거나 실행 파일에서 찾기)
- GF 트랙 머리의 0x16·0x17이 뜻하는 것, 노트 값의 `0x20` 비트, 0x08·0x0c 이외 칸
- `fre`의 7번째 값(늘 0?), 톤의 팬·ADSR을 소리에 반영할지, `music_info.bin`의 나머지 칸
- 열린 피크 레인(4K 네 번째)은 디스크에 열린 노트가 없어 늘 비어 있다. 와일링과 피크는 무시한다.

조사용 예제: `cargo run -p cs-disc --release --example gfdm_songs -- <image.iso> [<out dir>]`는 곡 표의 곡마다 이름, BPM, 레벨, 트랙별 노트 수를 보여 준다. 폴더를 주면 배너를 `m{id}.tga`로 쓴다. `--example gfdm_audio -- <image.iso> <out dir> [<id>...]`는 곡마다 음악 스트림, 미리 듣기, 채보 첫 트랙을 키음으로 그린 소리를 WAV로 쓴다. 번호를 안 주면 모든 곡의 스트림 수·길이와 소리 없는 노트 수를 보여 준다.
