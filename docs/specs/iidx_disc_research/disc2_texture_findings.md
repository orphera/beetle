# 디스크 2 텍스처·문자열 조사 정리

조사 대상: PREMIUM BEST 디스크(`SLPM_552.22`, `DATA1.DAT`). 목적은 곡 아티스트·장르·일본어 제목을 디스크에서 직접 얻을 수 있는지 확인하는 것이다.

## 1. 결론 요약

- 곡 제목(ASCII)은 실행 파일의 곡 테이블에 있다. (`0x17e0f0`부터 `0x134`바이트 레코드, 첫 0x20바이트가 이름)
- 아티스트, 장르, 일본어 제목은 **텍스트가 아니라 텍스처(이미지)** 로 들어 있다. 실행 파일과 압축 해제한 DATA1 항목 어디에서도 해당 문자열을 찾지 못했다.
- 아티스트·장르 글자는 아틀라스 텍스처에 모여 있고, 아틀라스 안에서 잘라 쓰는 사각형 표가 컨테이너 안에 있다.
- 현재 상태: 아틀라스 위치는 찾았지만, 곡과 사각형을 잇는 매핑은 두 곡에서만 확인했다. 외부 자료를 쓰는 방향으로 정했다.

## 2. 조사 방법과 결과

### 2.1 문자열 검색 (텍스트 여부)

| 대상 | 방법 | 결과 |
|---|---|---|
| 실행 파일 `SLPM_552.22`, `SLPM_552.21` | artist 이름(kors k, Honda, DJ TAKA 등), 일본어 제목(Shift-JIS) 검색 | 없음 (L.E.D만 우연히 1건) |
| DATA1 압축 해제 항목 (디스크 2, 128KB 이하) | Python 디코더 | 없음 |
| DATA1 압축 해제 항목 (디스크 2, 전체 3881개) | Rust 디코더(`tools\rs_scan`) | 없음. 나온 hit는 바이너리 우연 일치 |
| DATA1 압축 해제 항목 (디스크 1, 전체) | Rust 디코더 | 없음 |
| 압축되지 않은 DAT 파일 | 원본 바이트 검색 | 없음 |
| 곡 레코드 | 문자열 런 검색 | 곡 이름 외의 문자열 없음 |

검증: Rust 디코더가 Python 디코더와 같은 위치(항목 96의 1번, 오프셋 5270)에서 같은 문자열을 찾았다.

### 2.2 텍스처 추출

- 컨테이너 구조: `u16 data_offset`, `u16 count`, 이어서 `(압축 해제 크기, 압축 크기)` 쌍 `count+1`개. 파일 테이블은 실행 파일의 `0x139980`(디스크 2)에 16바이트 단위로 있다.
- 각 항목은 `sprites.decode_lzss`로 푼다. Rust 구현 `tools\rs_dump`가 디스크 2 전체 텍스처 항목을 `render_disc2\_raw\`에 저장했다(약 687MB).
- **텍스처 크기는 컨테이너 0번 항목(헤더)의 u16 쌍에서 읽는다.** 0x10부터 4바이트씩, k번째 텍스처는 `0x10 + 4×(k−1)`이다. 압축 해제 크기 − 0x400 으로 역산하면 가로·세로가 뒤집히는 경우가 있어서, 헤더 값을 써야 한다. 2408개 중 4개(컨테이너 1467, 1468)만 불일치했다.
- 포맷: PSMT8(8bpp), 파일 앞 0x400바이트가 CLUT(RGBA u32 × 256).
- 변환: `tools\render_disc2_png.py`가 스위즐 역변환을 크기별 순열로 미리 계산해서 빠르게 PNG로 바꾼다. 기존 `ps2textures.decode_ps2_texture`와 픽셀 차이 0을 확인했다.
- 결과: `render_disc2\c<컨테이너>_e<항목>_<가로>x<세로>.png` 2408장.

### 2.3 주요 텍스처 (확인된 내용)

| 파일 | 내용 |
|---|---|
| `c1313_e01_640x512.png` | 곡 제목 아틀라스 (영문 제목 다수) |
| `c1315_e01_640x192.png` | 아티스트 아틀라스 (영문·일본어 아티스트 이름, 아티스트 그림자 짧은 이름 다수) |
| `c1314_e01_640x192.png` | 장르 쪽 아틀라스로 보임 (확인 필요) |
| `c1312_e01_640x384.png` | 곡 제목 쪽 아틀라스 (사용자 확인) |
| `c0158_e05_384x512.png` | 메모리 카드 안내 문구 (시스템) |
| `c1453_e01_640x512.png` | ANISAKIS 로딩 카드 시트 (로고 포함) |

### 2.4 아틀라스 자르기

- 컨테이너 0번 항목(`c1315`의 경우)의 `0xd0`부터 8바이트 레코드가 사각형 `(x, y, w, h)`(u16)이다. 개수는 헤더의 `sprites` 필드(0x40 = 64)다.
- 64개 사각형으로 `c1315_e01`을 자르면 아티스트 이름이 한 줄씩 나뉜다. 결과: `render_disc2\sprites_c1315\`(64장), `render_disc2\sprites_c1315_sheet.png`.
- 자르기 자체는 정확했다. 사각형 번호와 이름의 대응은 아직 붙이지 않았다.

### 2.5 곡과 아틀라스의 연결 (가설)

- 곡 레코드의 `(인덱스, 컨테이너)` 쌍에서 컨테이너가 `0x523`(=1315)이면 인덱스가 `c1315`의 사각형 번호인 것으로 보인다.
- 확인된 두 곡:
  - ZERO-ONE: `(59, 0x523)` → 59번 사각형이 "Mr.T"로 보이고, 카드의 아티스트와 같다.
  - ANISAKIS: `(62, 0x523)` → 62번 사각형이 "朱雀"(카드의 한자 부제)로 보인다. 아티스트가 아니라 부제 데이터일 수 있다.
- 나머지 컨테이너(`0x520`, `0x521`, `0x522`)의 역할은 확인하지 않았다. `0x521`은 제목 아틀라스(c1313)로 보인다.

## 3. 활용 방안

- **플레이어에서 아티스트·장르를 이미지로 표시**: 텍스트가 필요 없으면 OCR 없이 사각형 이미지를 그대로 쓸 수 있다.
- **텍스트가 필요한 경우**: 사각형 번호마다 이름을 한 번만 붙이면 된다(수동 또는 외부 DB와 대조). 이름을 붙일 때 사각형 번호 ↔ 곡 매핑을 함께 검증해야 한다.
- **외부 자료**: 이번 조사에서 확인한 외부 후보는 tts1374 IIDX 곡 DB(SQLite, artist·genre·version), MASA-6cha/iidx-song-data(JSON), RemyWiki EMPRESS + PREMIUM BEST 목록이다. 아직 매칭은 하지 않았다.

## 4. 미해결

- `0x520`, `0x522` 아틀라스의 내용과 역할
- 곡 ↔ 사각형 매핑의 전수 검증(현재 2곡)
- 헤더 크기 불일치 4개(컨테이너 1467, 1468)의 포맷
- 디스크 1(EMPRESS)의 텍스처 전수 추출 (조사 대상이 아님)
- 채보(`.ply`) 본문 검색 (암호 해제 필요, 미수행)

## 6. 아틀라스 역할과 곡 레코드 연결 (확인됨)

곡 레코드(`0x134`바이트, 디스크 2 기준 `0x17e0f0`부터)의 **고정 위치**에 `(인덱스, 컨테이너 번호)` 쌍 4개가 있다. 모든 곡에서 같은 위치다.

| 레코드 바이트 | u16 워드 | 컨테이너 | 스프라이트 수 | 역할 (확인 결과) |
|---|---|---|---|---|
| `0xAC` | 86 | `0x522` (1314) | 71 | 장르 (ZERO-ONE: idx 26 → ELECTROSHOCK) |
| `0xB0` | 88 | `0x521` (1313) | 99 | 제목 (큰 제목 아틀라스 e02). 인덱스 62 → ZERO-ONE. 텍스처 선택 규칙은 아래 참고 |
| `0xB4` | 90 | `0x523` (1315) | 64 | 아티스트 (ZERO-ONE: idx 59 → Mr.T) |
| `0xB8` | 92 | `0x520` (1312) | 99 | 제목 (ZERO-ONE: idx 74 → ZERO-ONE) |

- 역할은 파일 안에 이름으로 적혀 있지 않다. **레코드 안의 슬롯 위치**와 **스프라이트 내용**을 맞춰서 확인한 것이다.
- 스프라이트 레코드 형식: 컨테이너 0번 항목의 `0xd0`부터 8바이트 `(x, y, w, h)`, 개수는 헤더 워드 3번(`sprites`)이다. 이 값이 각 컨테이너의 스프라이트 수와 일치했다(0x520=99, 0x521=99, 0x522=71, 0x523=64).
- `0x521`(c1313)은 텍스처가 3개(e01 640x512, e02 640x512, e03 640x192)다. 스프라이트 `y` 값이 한 장의 가상 세로 공간처럼 쓰인다.
  - 규칙: 가상 세로 공간에서 텍스처 기준 y는 e01 = 0, e02 = 1024, e03 = 2048이다. 스프라이트 `y`가 `[0,512)`면 e01, `[1024,1536)`면 e02(`y-1024`), `[2048,2240)`면 e03(`y-2048`)이다.
  - 99개 스프라이트 전부가 이 세 구간 중 하나에 들어갔다(e01 38, e02 44, e03 17).
  - 검증: 제목 12곡(ANISAKIS, BLUE RAIN, DAZZLIN DARLIN, RISTACCIA, BLIND JUSTICE, APOCALYPSE, HI SCHOOL DREAM, A, ZERO-ONE, DXY!, THE EARTH LIGHT, ERASER)을 규칙대로 잘라 보니 곡 이름과 모두 일치했다. 확인 이미지: `<iidx16_extract>\render\c1313_rule_check.png`.
- 같은 방식으로 `0x520`(c1312)은 한 장짜리라 `y`를 그대로 쓴다.
- 검증 예시: ZERO-ONE의 네 역할 중 장르(ELECTROSHOCK), 아티스트(Mr.T), 제목(ZERO-ONE)이 카드에 적힌 값과 일치했다.
