# PS2 GuitarFreaks 4thMIX & DrumMania 3rdMIX 디스크 형식

`crates/cs-disc`의 `gf4dm3.rs`가 읽는 PS2 GuitarFreaks 4thMIX & DrumMania 3rdMIX(`SLPM_650.52`) 디스크의 형식이다. 디스크 한 장과 실행 파일·사운드 드라이버의 기계어를 읽어 알아냈다(2026-11-15). Masterpiece Silver는 [gfdm_ps2_disc.md](gfdm_ps2_disc.md).

채보는 `gfdm::Seq`(1/300초)로 바꿔 Masterpiece Silver와 같은 `gfdm_bms`로 BMS를 만든다. 앱의 키도 같은 `gfdm/<id>/<파트><난이도>`다.

## 1. 디스크와 파일

| 경로 | 내용 |
|---|---|
| `SLPM_650.52` | 실행 파일(ELF) |
| `GF4DM3.DAT` | 게임 데이터 44개 (약 8MB) |
| `GF4DM3.SPK` | 소리 (`.sdd` 299개, 약 1.5GB) |
| `GF4DM3.BG` | 배경 (읽지 않음) |
| `DRIVER/SDDRV.IRX` | 사운드 드라이버. 곡의 `.sdd` 이름 표가 여기 있다 |

실행 파일 주소(가상 주소, 첫 프로그램 헤더로 파일 위치로 바꿈):

| 주소 | 내용 |
|---|---|
| `0x1fd450` | DAT 머리 키 48바이트 |
| `0x1fd480` | 곡 번호 `u32` × 49. 위치 `k`가 곡의 소리 번호 `k*6`을 정한다 |

## 2. `GF4DM3.DAT`

`u32` 파일 수(44) 다음 0x10부터 파일이 이어진다. 파일마다 0x30바이트 머리를 키로 XOR한 것, 그 뒤 본문(16바이트 정렬).

| 머리 위치 | 내용 |
|---|---|
| 0x00 | 이름 (NUL로 끝남, 최대 0x2b) |
| 0x2b | 종류 (`u8`) |
| 0x2c | 크기 (`u32`) |

쓰는 파일: `music_info/music_info5.bin`(곡 표), `seq/seqcode.dat`(채보 이름 해시), `seq/seqdata.dat`(채보), `texdat/gd_music_select.dat`(곡 제목 그림, 2.3).

### 2.1 `music_info5.bin`

실행 파일 `0x114e90`이 읽고, 그 뒤 `0x114f20`~`0x115374`에 필드마다 읽는 함수가 하나씩 있다(2026-11-15에 이 함수들로 확인).

| 위치 | 내용 |
|---|---|
| 0x00 | `u16` 레코드 수 *n*(145) |
| 0x02 | `u16` 표 항목 수 *m*(199) |
| 0x10 | 0x50바이트 레코드 × *n* |
| 0x10 + 0x50*n* | `(u16, u16)` 표 × *m* (레코드 0x34가 가리킴, 뜻 모름) |
| 그 뒤 | NUL로 끝나는 문자열 영역 |

레코드(실행 파일은 곡 번호로 이분 탐색한다):

| 위치 | 내용 |
|---|---|
| 0x00 | `u16` 곡 번호 |
| 0x02 | `u8`, 같은 `u16`의 비트 14·15는 플래그 (모름) |
| 0x04 | 8바이트 이름 (`ainosi`) |
| 0x0c | `u16` 문자열 영역 안 위치: 정식 제목 (`ai no shirushi`, `ANARCHY IN THE UK`, `dynamite`. 로마자, 아티스트는 없음) |
| 0x0e | `u16` 곡 길이 (1/75초, 마지막 노트와 몇십 틱 차이) |
| 0x10, 0x11 | `u8` (모름) |
| 0x12 + 2*i* | `u16` 제목 *i*번째 줄의 문자열 위치 (두 줄로 나눈 제목) |
| 0x16 + 2*i*, 0x17 + 2*i* | `u8` 두 개, 줄마다 (모름, 배치로 보임) |
| 0x1a | `u8` 제목 줄 수 (1·2) |
| 0x1b + *k* | `u8` 모드 *k*의 레벨(1~10). 0이면 그 모드 목록에 곡이 없다 |
| 0x22 + 4*k* | `u16` 두 개, 모드마다 (모름) |
| 0x30, 0x32 | 0x30이 0이 아니면 0x32의 `u16`을 쓴다 (1175·롱 버전에만 있음, 모름) |
| 0x34 | `u16` 위 표의 시작 번호 |
| 0x36 | `u16` (모름) |
| 0x40 | `u16` 곡 길이 (0x0e와 비슷한 값) |
| 0x44 | `u16`의 비트 7·6이 플래그. 보통 곡 `c0`, 롱 버전·1175 `40`, 디스크에 반주가 없는 곡 일부 `80` |
| 0x48 + *k* | `u8` 모드 *k*의 값(85~250, 모름) |

모드 *k*는 게임 모드 0~7을 실행 파일 `0x1e7638`의 표 `(0, 1, 2, 3, 4, 5, 5, 6)`로 바꾼 것이고, 채보와 맞춰 보면 다음과 같다(레벨이 있는 곳과 그 채보가 있는 곳이 같다).

| *k* | 레벨이 있는 곡에 있는 드럼 채보 |
|---|---|
| 0 | `prac` |
| 1 | `easy` |
| 2 | `norm` |
| 3 | `real` |
| 4 | `expr` |
| 5 | `lnkn`·`lnkx` (게임 모드 5·6이 함께 씀) |
| 6 | `bnus` (롱 버전과 1175만) |

예: RIGHT ON TIME 0·0·4·7·8·7·0, YOU ELEVATE ME 0·0·6·7·10·7·0. 레벨이 드럼 채보에 맞춰져 있어 드럼 레벨로 보인다. 기타 레벨이 따로 있는지는 모른다(기타 `nor`·`exp`·`ex1`·`ex2`는 박자가 같고 운지만 다르다: `ex1` 단음 위주, `ex2` 화음 위주, `exp`는 `nor`에 와일링). 디스크에 반주가 없는 곡(KILLER QUEEN, 桜の時, STAY AWAY 등)은 레벨이 모두 0이다.

앱은 정식 제목(0x0c, 없으면 이름을 대문자로)을 제목 글자에, 목록에는 제목 그림(2.3)을 그린다. 드럼의 앱 난이도 1·2·3 레벨은 *k* = 2(0이면 1)·3·4이고, 기타·베이스 레벨은 비워 둔다.

### 2.2 채보: `seqcode.dat`, `seqdata.dat`

`seqdata.dat`: `u32` 채보 수(1306), 0x10부터 `u32` 위치 표(비트 31이 서 있으면 압축됨). `seqcode.dat`: 채보마다 이름의 해시 `u32`.

해시: `h = ((h << 5) | (h >> 23)) + c; h &= 0x0fffffff` (결과가 0이면 1). 충돌이 잦아서 게임처럼 **처음 일치하는 항목**을 쓴다.

이름:

- 기타 `seq%03d_%s%s`: 곡 번호, `1p1`(싱글 기타)·`1p2`(대부분 빔)·`2p1`/`2p2`(세션 기타/베이스), 난이도 `nor`·`exp`·`ex1`·`ex2`·`pra`
- 드럼 `seq%03d%s`: `norm`·`easy`·`real`·`expr`·`prac`·`lnkn`·`lnkx`·`bnus`

앱의 난이도: 기타(`1p1`)·베이스(`2p2`) 1 = `nor`, 2 = `exp`(없으면 `ex1`), 3 = `ex2`(없으면 남은 `ex1`). 드럼 1 = `norm`(없으면 `easy`), 2 = `real`, 3 = `expr`.

압축(실행 파일 `0x1bdc50`, 그 뒤 `0x1bc790`) 두 단계:

1. 정준 허프만: `u32` 출력 길이, 그 뒤 MSB부터 읽는 비트열. 먼저 바이트 256개의 부호 길이: 비트 1이면 `길이 = gamma() ^ 이전 길이`, 0이면 이전 길이 그대로. `gamma`는 0을 센 뒤 1, 그만큼 비트를 더 읽는 Elias 감마. 부호는 짧은 길이부터, 같은 길이는 바이트 순으로 붙인다(최대 16비트).
2. Konami LZ: `cs_disc::lz::decode`와 같다.

이벤트는 8바이트, 시간 단위는 **1/75초**(드럼 채보와 반주의 음량 변화 상관으로 확인). 모든 바이트가 0인 이벤트가 끝이다.

드럼: `u32` 시각, `u8` 종류(0~5 레인 HH SD BD HT LT CY, 6 레인 없는 소리, 7 마디선, 8 박선), `u8` 음량, `u16` 키(뱅크에서 그 키를 맡은 음색).

기타: `u16` 시각, `u16` 음색 번호, `u16` 길이(1/75초), `u16` 플래그(비트 0~2 R·G·B, 0x20 와일링으로 추정, 0x40 세션 채보에만, 0x08 드묾). 길이 0·플래그 0x10은 마디선이고, 시각 0xffff의 마디선은 끝 표시다.

`gfdm::Seq`로 바꿀 때: 마디선이 1/75초로 반올림되어 있어(130 BPM이면 마디가 138·139틱) 마디마다 템포를 만들면 BPM이 흔들린다. 그래서 드럼 채보의 마디선을 고른 구간으로 나눠 구간마다 템포 하나를 맞춘다(`beat_grid`). 마디의 박 수는 그 안의 박선 수 + 1이고, 마디 길이가 지금 구간의 박 길이 × 박 수에서 1.5틱 넘게 벗어나면 새 구간이다. 0.03 안쪽이면 정수 BPM으로 반올림한다. 결과는 대부분 정수 BPM 하나(130, 132, 160…). 마디선은 맞춘 박 격자로 옮긴다. 기타·베이스도 드럼의 템포를 쓰고 마디선만 자기 것을 쓴다(기타 채보에는 박선이 없고 2박 마디가 있다). 드럼 채보가 없는 곡(1175)은 기타 마디선으로 맞추되, 박 수는 앞 마디의 박 길이에 맞는 1~8 중 하나(없으면 4). 메들리(CLASSIC PARTY 2, 1175)는 실제로 템포가 자주 바뀐다. DAY DREAM은 중간부터 박선이 마디선과 다른 격자에 있다(마디 112.5틱, 박선 26.5틱). 기타 노트의 `a`는 음색 번호, 위 16비트에 길이(1/300초).

### 2.3 그림: `texdat/*.dat`

`u32` 그림 수, 0x10부터 `u32` 위치 표. 비트 31이 서 있으면 채보와 같은 허프만+LZ, 아니면 LZ만이다. 풀면 PlayStation TIM(`0x10`, 플래그 8 = 4비트, 9 = 8비트, 16비트 색 표, 색 0은 투명)이다. 디스크의 `texdat/*.dat` 42개에서 TIM 2196장이 나온다(`hdd_err`·`sn_flame`·`system`의 일부는 다른 형식).

`gd_music_select.dat`의 0~45번이 곡 제목 그림(224×32)이다. 순서는 실행 파일 곡 표(1.)의 49곡 가운데 RIFF 연습곡(`riff41`~`riff43`, 제목 그림 없음)을 뺀 46곡의 곡 번호 순. 46번은 `???`, 47~91번은 64×112 그림이다. 앱은 이 그림을 Masterpiece Silver의 제목 그림처럼 선곡 목록에 그린다(이름 파일 `gf4dm3.names`).

## 3. `GF4DM3.SPK`

처음 0x4000바이트만 뒤섞여 있다: `p[0] = c[0]`, `p[n] = c[n] ^ (c[n-1] + n)` (바이트 연산). 풀면:

| 위치 | 내용 |
|---|---|
| 0x04 | 전체 크기 |
| 0x08 | 파일이 시작하는 곳(0x4000) |
| 0x0c | 파일 수(299) |
| 0x40 | 16바이트 항목: `u32` 크기, `u8` 이름 길이, 이름 |

파일은 0x4000부터 순서대로 이어진다.

곡마다 `.sdd` 여섯 개:

| 이름 | 뱅크 | 반주 |
|---|---|---|
| `g1_<코드>.sdd` | 기타 | 기타를 뺀 반주 |
| `g2_<코드>.sdd` | (없을 수 있음) | 베이스를 뺀 반주 |
| `d1_<코드>.sdd` | 드럼 | 드럼을 뺀 반주 |
| `d2`, `d3` | 둘 다 | 세션용 |
| `pr_<코드>.sdd` | 없음 | 미리 듣기 |

반주가 연주하지 않는 파트를 이미 담고 있으므로 다른 파트의 키음은 내지 않는다(`Kits::identity`, `music_has_others`). `L_` 곡과 `1175`의 `g2`처럼 반주가 1초도 안 되면 앱은 `g1`의 반주를 쓴다.

### 3.1 곡 → `.sdd`

곡 번호 표(`0x1fd480`)의 위치 `k`에서 소리 번호 `k*6 + 파트`(g1 0, g2 1, d1 2, d2 3, d3 4, pr 5). `SDDRV.IRX`의 두 번째 프로그램 헤더가 올리는 이미지의 64960바이트 위치에 8바이트 항목 `(이름 포인터, 0x1880)`이 소리 번호 순으로 있다. 곡 코드는 이름의 4~6번째 글자다. 이 디스크에 반주가 없는 곡 5개(313, 241, 351, 363, 365)는 `tak`의 파일을 가리키므로 뺀다. 남는 곡 44개 중 RIFF 연습곡 2개는 채보가 없어 앱 목록에는 42곡이 나온다.

### 3.2 `.sdd` (`SDDT`)

평문. 0x0c에 `u32` 구획 수, 0x40부터 `(위치, 크기)` 쌍. 구획 순서: `VSHD`(스트림 머리, 44100Hz, 인터리브 0x1000), `VPHD`들, 같은 순서의 뱅크 본문들, 마지막이 반주 스트림.

`VPHD`(VAB 비슷): 0x0e에 `u16` 음색 수, 0x40부터 프로그램 `<u16 첫 음색, u8 수, u8 음량>`, 0x240부터 음색 0x20바이트:

| 위치 | 내용 |
|---|---|
| 2 | 음량 (0~127) |
| 3 | 팬 (0~127, 64가 가운데) |
| 4 | 기준 키 |
| 6, 7 | 맡는 키 범위 |
| 0x0c | 본문 안 위치 (`u32`, 16바이트 단위) |
| 0x10 | 크기 (`u32`, 16바이트 단위) |

드럼 노트는 키 범위로 음색을 찾고 `44100 × 2^((키 − 기준 키)/12)`로 재생한다(가정, 귀로는 맞음). 기타 노트는 음색 번호의 음색을 그 음색이 맡는 키(6번 바이트)로 낸다. 기타 음색은 기준 키가 맡는 키보다 대개 12, 몇몇은 18~25 높아서, 기준 키로(44100Hz 그대로) 내면 한 옥타브 넘게 높게 들린다(B30). 기타가 든 반주(`g2`)에서 기타를 뺀 반주(`g1`)를 뺀 소리와 스펙트럼을 대 보면, 맡는 키로 낸 쪽이 가장 잘 맞았다(RIGHT ON TIME 0.36 대 기준 키 0.29, 愛のしるし 0.41 대 0.32). 5번 바이트(0, 116, 124 등)는 미세 음높이로 보이지만 아직 쓰지 않는다.

반주: 스테레오 PS-ADPCM, 채널마다 0x1000바이트씩 번갈아, 44100Hz.

## 4. 재생

- 기타 키음은 노트 길이만큼 내고 64샘플 동안 줄여 끈다. 끝까지 내면 꼬리가 최대 6개 겹쳐 지저분하다(사용자가 귀로 확인, Masterpiece Silver와 같은 문제).
- 키음이 반주보다 약 40ms 일찍 들린다. 채보와 반주를 대 보면 드럼은 몇 ms 차이뿐이지만, 귀로는 키음 전체를 40ms 늦춘 쪽이 가장 잘 맞았다(2026-11-15). 그래서 반주 앞 1764샘플(`MUSIC_LEAD`)을 버린다.
