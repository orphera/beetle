# 컨트롤러 (Controllers)

Beetle은 두 종류의 컨트롤러를 받는다. 둘 다 새 크레이트 없이 OS DLL을 직접 FFI로 부른다.

- **XInput 패드** (Xbox 계열): 메뉴 조작 전용. `xinput1_4.dll`을 실행 중에 `LoadLibraryExW`(`LOAD_LIBRARY_SEARCH_SYSTEM32`)로 올린다(없으면 `xinput1_3.dll`, `xinput9_1_0.dll`). 시스템 폴더에서만 찾아서, 사용자가 쓸 수 있는 앱 폴더의 DLL은 로드되지 않는다. 링크 시점 의존이 없어서 DLL이 없어도 실행된다.
- **HID 게임 컨트롤러** (IIDX 컨트롤러, 아케이드 패드, DJ 턴테이블, 버튼이 많은 게임패드): Raw Input(`WM_INPUT`, `RIM_TYPEHID`)으로 받아 `hid.dll`로 해석한다. **레인 입력**이다.

구현은 `crates/beetle-app/src/xinput.rs`(메뉴), `crates/beetle-app/src/hid.rs`(HID 해석), `crates/beetle-app/src/turntable.rs`(턴테이블), `crates/beetle-app/src/raw_input.rs`(입력 스레드)에 있다.

## 1. XInput: 메뉴 조작

패드는 키보드 핸들러와 같은 동작을 부른다. 메뉴 화면은 패드 전용 코드가 없다. 폴링은 메인 루프(`about_to_wait`)에서 한다. 패드가 연결되어 있고 포커스가 있는 메뉴 화면이면 16 ms마다 깨어나 폴링한다(저사양 WARP 모드에서도 같다). 화면이 입력을 기다리며 잠들어 있어도 패드를 듣는다. 연결된 패드가 없으면 1초마다 빈 슬롯 하나만 본다(0→1→2→3 순환, 4초에 한 바퀴). 플레이 중(일시정지 전)에는 스캔하지 않는다. 빈 슬롯 읽기는 밀리초가 걸릴 수 있어서다.

| 입력 | 메뉴 (키보드 동등) | 플레이 중 |
|---|---|---|
| 방향패드 / 왼쪽 스틱 | 방향키 ↑ ↓ ← → | 없음 |
| A | Enter | 없음 |
| B | Esc | 없음 |
| X | 키 A (자동 재생 토글, 선곡) | 없음 |
| Y | Tab (옵션) | 없음 |
| Start | Enter | Esc (일시정지) |
| Back | F4 (설정) | 없음 |
| LB / RB | PageUp / PageDown | 없음 |
| LT / RT (누르는 순간) | F1 / F3 (폴더 이전 / 다음) | 없음 |

- 스틱: 크기 0.35 이상에서 방향이 켜지고 0.25 아래로 내려가야 꺼진다(히스테리시스). 방향패드가 눌려 있으면 스틱보다 우선한다.
- 자동 반복: 방향은 누른 뒤 350 ms 후 한 번 더 나가고, 그다음 90 ms마다 나간다. 오래 걸린 프레임은 한 번만 반복한다(몰아서 나가지 않는다).
- 플레이 중에는 Start만 게임으로 간다. 일시정지 메뉴에서는 위·아래·A·B도 간다.
- 패드 상태는 입력이 받아들여지지 않을 때도 계속 따라간다(버린 것은 이벤트뿐이다). 그래서 받아들여지지 않은 동안 누르고 있던 버튼은 나중에 새 누름으로 읽히지 않는다.
- 키 설정의 "키 누르기" 대기 중에는 패드 메뉴 입력을 버린다(A가 Enter를 지정하지 않도록).
- 패드 버튼이 키 설정에 바인딩되면 같은 누름이 XInput에도 오므로, 그 뒤 **250 ms** 동안 패드 메뉴 입력을 무시한다.
- 창이 포커스를 잃으면 입력을 버린다. 포커스를 되찾으면 현재 상태를 기준으로 삼는다(그사이 바뀐 것은 누름이 아니다).

## 2. HID: 레인 입력

### 2.1 장치와 보고서

- 등록: 키보드와 같은 메시지 전용 창에 `RIDEV_INPUTSINK`로 usage page `0x01`, usage `0x04`(조이스틱)와 `0x05`(게임패드)를 등록한다. `RIDEV_DEVNOTIFY`로 장치 제거를 알린다. HID 등록이 실패해도 키보드는 그대로 동작한다.
- 장치마다 `HidP_GetCaps` / `HidP_GetButtonCaps` / `HidP_GetValueCaps`로 구조를 한 번 읽어 캐시한다(장치 핸들 기준). 해석할 수 없는 장치는 다시 묻지 않는다. 장치는 입력 스레드 시작 때 이미 연결된 것을 열고, 도착 통지(`GIDC_ARRIVAL`)로 새로 연결된 것을 연다. 첫 보고서에서 처음 여는 것은 예비 경로다.
- 보고서마다 `HidP_GetUsages`(버튼)와 `HidP_GetUsageValue`(축)를 부른다. 보고서가 너무 짧거나 너무 길거나 hid.dll이 거부하면 그 보고서는 버린다(패닉 없음).
- 장치가 제거되면 그 장치가 누르고 있던 버튼은 모두 떼어진 것으로 처리한다.

### 2.2 버튼과 축

| 항목 | 규칙 |
|---|---|
| 버튼 | HID usage `n` (1..=64)이 버튼 `n`이다. 화면에는 `PAD n`으로 나온다. |
| 축 | 값 컨트롤을 장치 능력 순서로 0..7번 축에 붙인다(범위 usage는 usage마다 한 축). 8개를 넘는 컨트롤은 무시한다. |
| 정규화 | 논리 최소·최대에서 0..=65535로 바꾼다. 논리 최소가 음수면 비트 폭 기준으로 부호를 확장한다. |
| 원시값 | 턴테이블 판정에는 정규화 전의 원시값(비트 폭 기준)을 쓴다. |

### 2.3 턴테이블 (스크래치)

- 설정 `turntable_axis=<0..7>`을 쓰면 그 축이 턴테이블이다. **기본값은 없음(꺼짐)**이다. 기본을 축 0으로 두면 게임패드의 왼쪽 스틱이 스크래치를 계속 누르게 되므로 끈다.
- 보고서 사이의 원시값 차이를 비트 폭 기준으로 wrap-aware하게 구한다(8, 10, 16비트 모두). 차이의 부호가 방향(`Cw`/`Ccw`)이다.
- 방향마다 따로 누른다: `Source::TurntableCw`와 `Source::TurntableCcw`. 둘 다 스크래치 레인이다.
- **누름 시작**: 같은 방향으로 움직인 양이 **2 원시 단위** 이상 쌓이면 누른다. 쌓임은 보고서를 가로질러 더하므로 느린 회전(보고서마다 1 단위)도 누른다. 쌓임에는 시간 제한이 없다.
- **유지**: 누른 동안 같은 방향의 움직임(1 단위라도)은 마지막 움직임 시각을 갱신하고 계속 누른 상태로 둔다.
- **방향 전환**: 반대 방향으로 1 단위 이상 움직이면 옛 방향을 떼고(release), 쌓임을 0부터 새 방향으로 센다. 새 방향이 2 단위 쌓이면 새 누름이다(IIDX / LR2 관례). 한 보고서에 떼고 누르는 것이 함께 일어날 수 있다.
- **떼기**: 마지막 움직임 뒤 **60 ms**가 지나면 뗀다. 타이머는 입력 스레드의 미스 확인 틱(4 ms)에서 돈다.
- 지터(정지 근처에서 ±1 단위를 오가는 것)는 방향이 매번 바뀌므로 누르지 않는다. 누른 뒤 지터는 전환으로 보여 떼어지고, 다시 2 단위가 쌓여야 누른다.
- 상태는 장치마다 따로다(`hid::Device`가 `Turntable`을 가진다). 같은 축 번호를 쓰는 다른 장치(예: 게임패드 스틱)의 값은 이 턴테이블의 쌓임이나 누름을 바꾸지 않는다. 턴테이블 축 번호는 모든 장치에 같게 적용된다.
- 두 장치가 동시에 턴테이블로 누르면 같은 스크래치 레인을 공유한다. 한 장치가 떼면 레인이 떼어질 수 있다(한계).
- 판정 시각은 오디오 클럭(`AudioClock::time_at`)이다.
- 플레이 중에만 동작한다. 턴테이블은 항상 스크래치 레인(`Lane::Scratch`)으로 간다.

### 2.4 판정 경로

HID 버튼 변화는 키와 같은 경로를 탄다. 입력 스레드가 도착 시각(`Instant`)을 찍고, 플레이 중이면 `AudioClock::time_at(도착 시각)`으로 판정하고 키음을 낸다(INV-1, INV-4). 플레이가 아니면 `RawKey`로 메인 스레드에 넘긴다. 렌더 스레드는 판정을 하지 않는다.

## 3. 바인딩 형식

레인에는 키와 패드 버튼을 함께 붙일 수 있다. 같은 레이아웃(Custom)에 저장되고, 기존 `key_bindings_<모드>` 문자열에 항목만 추가된다.

```
key_bindings_7k=Scratch:ShiftLeft,Key1:KeyS,Key1:Pad3,Key1:Pad40,Key2:KeyD,...
```

| 토큰 | 뜻 |
|---|---|
| `KeyS` 같은 키 식별자 | 키보드 키 (기존 형식) |
| `Pad<n>` | 패드 버튼 n (장치 슬롯 0) |
| `Pad<slot>.<n>` | 슬롯 `slot`의 패드 버튼 n. 현재 UI는 슬롯 0만 만든다. |

- `n`은 1..=64이다. 그 밖의 값, 알 수 없는 항목은 읽을 때 건너뛴다.
- 이전 빌드의 파일은 그대로 읽힌다(패드 항목이 없다). 패드 항목이 있는 파일을 이전 빌드가 읽으면 그 항목만 무시된다.
- 키 설정 화면에서 "키 지정"(Enter) 또는 "키 추가"(A) 중에 패드 버튼을 누르면 그 레인에 바인딩된다. 지정은 같은 종류(패드끼리)만 바꾸고, 키는 그대로 둔다. Backspace는 레인의 키와 패드 버튼을 모두 지운다.
- 설정 파일의 `turntable_axis=<0..7>`은 턴테이블 축이다. `OFF`나 줄이 없으면 없음이다.

## 4. 한계

- **버튼에는 장치 구분이 없다.** 연결된 모든 컨트롤러의 버튼은 슬롯 0이다. 두 개를 같이 쓰면 같은 버튼 번호는 같은 바인딩을 공유한다. (턴테이블 상태만 장치마다 따로다, 2.3 참고.)
- **축 번호는 장치 능력 순서다.** 축 0이 턴테이블 X축이라는 보장은 없다. 장치마다 `turntable_axis`를 확인해야 한다.
- 턴테이블 축은 설정 파일로만 정한다. 설정 화면에는 행이 없다.
- HID 입력에 데드존·보정은 없다. 축은 보고된 값을 그대로 쓴다.
- 패드가 연결되지 않은 메뉴는 1초마다(슬롯 하나씩) 스캔하고, 창이 포커스를 잃은 동안에는 패드를 깨워 폴링하지 않는다. 포커스를 되찾을 때 현재 상태를 기준으로 삼는다.
- XInput 레거시 DLL(`xinput1_3`, `xinput9_1_0`)은 이름 `XInputGetState`로만 찾는다(서수 대체 경로는 없다).
- 패드 진동(rumble), 조명, 인증 모드(Xbox 인증 HID)는 다루지 않는다.
- 실기 검증은 되어 있지 않다. 단위 테스트는 합성 캡 구조체와 보고서 값만 쓴다.
